# 폴더 정리 앱 계획 (Nook 방식)

**결정 (2026-10-20, 사용자):** Capture One 연동 대신 **폴더별로 정리해 주는 방식**으로 간다. 화면은 사용자가 Day5에서 만든 **Nook**(누끼 앱)과 같은 방식으로 만든다. Capture One 연동(`apply`, `albums`, `rollback`)은 지우지 않고 선택 기능으로 남긴다.

## 1. Nook에서 가져올 것 (읽어 본 결과, 실행해 보지는 않음)

Day5의 `Nook/cutout-app`을 읽었다. 구조는 이렇다.

| 구성 | 내용 |
|---|---|
| **Electron 셸** (`electron/main.js`) | 앱 창. 로컬 Python 서버를 띄우고 그 주소를 창에 보여 준다 |
| **로컬 Python 서버** (`server.py`) | `127.0.0.1`의 빈 포트에만 열고, 실행할 때마다 **무작위 토큰**을 만들어 API 호출에 요구한다 |
| **화면** (`web/`: HTML + JS + CSS) | 서버가 내려준다. 사진 끌어다 놓기, 도구 막대, 옵션 패널, 라이트/다크 |
| **빌드** (`electron/build.sh`) | **Node/npm 없이** Electron 공식 배포본(`.cache/electron-v44.7.0`에 이미 받아 둠)만 써서 `~/Applications/Nook.app`을 조립. 파이썬 환경과 모델은 `~/Library/Application Support/Nook/runtime`으로 복사해 쓴다(Desktop은 iCloud 동기화라 코드 서명과 폴더 접근 허용 창이 문제가 되기 때문) |

이 방식은 "내 Mac 전용, 모든 처리가 내 Mac 안"이라는 점에서 이 프로젝트의 약속(사진이 컴퓨터 밖으로 나가지 않는다)과 맞다. **같은 구조를 그대로 재사용**한다. 확인한 것: 지금 `~/Applications/Nook.app`은 설치돼 있지 않고, Electron 캐시는 남아 있다.

## 2. 이 프로젝트에서 달라지는 점

1. **네트워크 안전 규칙을 부분적으로 풀어야 한다.** 지금은 `http`, `socket` 같은 네트워크 모듈 import를 코드 전체에서 금지하고 테스트가 검사한다. 로컬 서버는 이 모듈이 필요하다. **풀 범위를 한 모듈로 좁힌다:** `bcut/ui/server.py`만 허용하고, ① `127.0.0.1`에만 열기, ② 토큰 없는 요청 거부, ③ 외부로 나가는 접속(urllib, requests 등)은 계속 금지, ④ 나머지 모든 모듈은 지금처럼 금지 — 를 **테스트로 고정**한다.
2. **판정 코드는 건드리지 않는다.** 홀드아웃 동결 때문에 `score/`, `detect/`, `imageio/`, `scan.py`, `config.py`는 수정하지 않는다. 정리 기능은 새 모듈(`organize.py`, `ui/`)에 만들고 `scan`의 결과를 가져다 쓴다.
3. **원본 폴더는 계속 읽기 전용이다.** 사진을 옮기거나 지우지 않는다. **복제본**(APFS 복제, 같은 디스크면 시간·공간이 거의 안 듦)을 별도 폴더에 만든다.

## 3. 정리 결과의 모양

```
<결과 폴더>/<행사>_정리_2026-10-20_1530/
  버릴 것 같은 컷/    눈 감김 후보 (candidate)
  직접 확인/          사람이 확인할 컷 (review)
  이상 없음/          나머지 + 사용자가 "남기기"한 컷
  문제 종류별/눈 감김/, 너무 밝거나 어두움/, 흔들려 찍힘/, 초점이 안 맞음/   (해당하는 컷의 복제, 선택)
  정리 기록.json     어떤 파일이 어느 폴더로 갔는지, 도구·설정 버전
```
- **실행마다 새 폴더**(시각 포함)를 만든다. 이 도구는 파일 삭제 호출을 쓰지 않는 규칙이라, 이전 결과를 지우고 다시 만들 수 없다. 필요 없는 결과 폴더는 Finder에서 직접 지운다.
- **한 컷이 여러 사유**에 걸리면: 등급 폴더(후보/확인/정상)에는 한 번만 들어가고, 사유별 폴더에는 해당하는 사유마다 들어간다 (복제라 공간 부담이 작다).
- **미리보기가 기본**이다: 몇 장이 어느 폴더로 갈지 먼저 보여 주고, 확인해야 만든다.
- **같은 디스크가 아니면**(외장 드라이브로 정리) 복제가 아니라 복사가 된다. 사진당 약 24MB가 실제로 든다. 이 경우 장수와 용량을 미리 알려 준다.

## 4. 화면 흐름 (Nook의 구조를 따른다)

1. **사진 폴더를 창에 끌어다 놓기**(또는 폴더 열기).
2. **분석** 진행률(장수/전체) → 요약: 후보 N, 확인 N, 정상 N, 판정 불가.
3. **썸네일 그리드**: 후보·확인 컷을 사유별로 필터, 확신도 순 정렬 (지금 HTML 리포트의 화면을 재사용). 사진을 눌러 크게 보기(확대 100%).
4. **살리기**: 좋은 컷을 표시하면 "정상"으로 간다 (기존 HTML 리포트의 "살리기"와 같은 개념).
5. **폴더로 정리** 버튼 → 미리보기(어느 폴더로 몇 장) → 확인 → 결과 폴더를 Finder로 열기.
6. 설정(눈 감김 기준 등)은 고급 패널에 두고, 기본값으로 바로 쓸 수 있게 한다.

## 5. 작업 쪼개기와 대략 비용 (추정)

| 단계 | 내용 | 대략 |
|---|---|---|
| **S1** `bcut sort` (명령줄) | 정리 엔진: 미리보기, 복제, 폴더 구조, 기록, 안전 검사(원본 불변, 외부 폴더만) — **완료 (2026-10-20)** | 반나절~1일 |
| **S2** 로컬 서버 | `bcut/ui/server.py`: 127.0.0.1 + 토큰, 분석·썸네일·정리 API, 안전 규칙 테스트 — **완료 (2026-10-20)** | 1~2일 |
| **S3** 화면 | 폴더 끌어놓기, 진행률, 그리드·필터·확대·살리기, 정리 흐름 (기존 HTML 리포트 코드 재사용) — **완료 (2026-10-20), 끌어놓기·맥 폴더 창은 S4에서 확인** | 2~3일 |
| **S4** 앱 껍데기 | Electron 셸 + 빌드 스크립트(Nook 것을 복제), `~/Applications`에 설치, 파이썬 환경 복사 — **빌드·설치 완료 (2026-10-20), 화면 조작 확인은 사용자 대기** | 1일 |
| **S5** 시험 | 단위·통합 테스트, 실제 행사(400장·560장)로 리허설 | 1일 |

합계 약 1주 (1인, 추정). **S1은 명령줄이라 바로 쓸 수 있고**, S2~S4는 그 위에 얹는다. 순서대로 만들면 각 단계가 끝날 때마다 쓸 수 있는 것이 생긴다.

## 6. 확정한 것 (2026-10-20, 사용자)

- **네트워크 규칙 완화 승인:** `bcut/ui/server.py` 한 모듈만 허용(127.0.0.1에만 열기, 토큰 필수, 외부 접속 금지를 테스트로 고정). 나머지 모든 모듈은 지금처럼 금지.
- **"살리기"한 컷은 `정상` 폴더에 합친다.** 후보·확인 폴더에는 남지 않는다.

## 7. 아직 정하지 않은 것

- 앱 이름(가칭 `bcut`), 디자인(Nook의 팔레트를 쓸지)
- 사유별 폴더를 기본으로 만들지 여부
- 홀드아웃 평가 전에 시작할지 (정리 기능은 판정 코드를 건드리지 않으므로 병행 가능)

## 화면 개편 (2026-10-20)
결과 화면은 우선순위 구조다: 1순위(버릴 것 같은 컷) → 2순위(직접 확인) → 남긴 컷 → 이상 없음 → 판단 못 함 순으로 구역을 나누고, 구역 안은 의심 정도 순. 스타일은 밝고 가벼운 카드형(라이트/다크). 세로 사진은 서버가 방향값으로 돌려 내려준다.
