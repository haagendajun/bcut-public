# 분류 규칙 (T1.8) — 등급과 확신도

작성: 2026-10-19. 구현: `bcut.scan` (`combine_status`, `confidence_of`, `eyes_strength`), `bcut.config`.

## 1. 등급 (사진 한 장의 결과)

| 등급 | 뜻 | 어떻게 정해지나 |
|---|---|---|
| `candidate` | B컷 후보 | 사유 중 등급이 `candidate`인 것이 하나라도 걸렸을 때 |
| `review` | 사람이 확인 | `candidate`는 없고, 등급이 `review`인 사유가 걸렸을 때. 읽기 실패, 눈이 너무 좁음, 단체 사진의 눈 감김도 여기로 온다 |
| `normal` | 정상 | 얼굴이 있고 어떤 사유도 안 걸림 (A컷이라는 뜻이 아니다) |
| `no_face` | 얼굴 없음 | 눈 감김 판정 대상이 없고 다른 사유도 안 걸림 |
| `unscorable` | 판정 불가 | 눈 감김을 믿을 수 없는 경우 (얼굴 각도·크기) 중 다른 사유도 없음 |

규칙은 **가장 높은 등급이 이긴다** (`candidate` > `review` > 나머지). 걸린 사유는 모두 `reason` 열과 리포트에 남는다.
**확신이 낮으면 `review`** (제약 C5): 사유별로 "정말 B컷일 가능성이 낮은" 경우는 판정기가 처음부터 `review`로 보낸다 (단체 사진, 좁은 눈, 경계 구간 점수, 흔들림·초점·노출 전부).

## 2. 사유별 기본 등급 (증거 기반, devplan 1-F)

| 사유 | 기본 등급 | 근거 |
|---|---|---|
| `eyes_closed` | `candidate` (경계 구간은 `review`) | 실제 결함 48장으로 검증 |
| `exposure` | `review` | 실제 결함 0장 |
| `blur`, `out_of_focus` | `review` (각각 따로 설정) | 실제 결함 2장 |

설정 파일 `[reason_tiers]`에서 사유별로 바꾼다. 실제 결함 20장 이상으로 검증되면 `candidate`로 올린다.

## 3. 확신도 (`confidence`, 0~1)

**확률이 아니라 정렬용 점수다.** "이 컷이 B컷일 확률"이 아니라 "먼저 볼 순서"를 정하는 데 쓴다. 걸린 사유가 없으면 비어 있다.

1. 사유마다 강도 `s`(0~1)를 구한다.
   - 눈 감김: `candidate`는 `1 - 점수/후보 경계` (점수가 0에 가까울수록 1), `review`는 `1 - (점수-후보 경계)/(확인 경계-후보 경계)` (확인 경계에 가까울수록 0)
   - 노출, 흔들림, 초점: 각 모듈의 심각도(`exposure_severity`, `sharpness_severity`)
2. 사유의 등급이 `candidate`면 `0.5 + 0.5·s`, `review`면 `0.5·s`로 옮긴다.
3. 사진의 확신도는 사유별 값 중 **가장 큰 값**이다.

그래서 검증된 사유(후보 등급)는 검증 안 된 사유(확인 등급)보다 항상 위에 온다. 설정으로 등급을 바꾸면 확신도 범위도 같이 바뀐다. CSV의 `confidence` 열과 HTML 리포트의 "확신도 높은 순" 정렬에 쓴다.
한계: 강도는 임계값에서 얼마나 멀리 있는지일 뿐이라, 서로 다른 사유의 강도를 같은 척도로 비교하는 것은 근사다.

## 4. 실행 로그 (`bcut-log.json`, FR-11)

`scan`이 결과 폴더에 쓴다: 시작·종료 시각, 장수, 소요 초와 장당 초, 등급별·사유별 개수, 판정 불가 이유별 개수, 처리 못 한 파일(이유 포함), 설정 버전·사유별 등급·임계값. 사진 내용은 담지 않는다.
