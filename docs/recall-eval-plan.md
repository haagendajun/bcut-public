## 1. 문제

`260212 EVENT_B STRX SJ`의 라벨링 결과 (145장):

| 라벨 | 장수 | 의미 |
|---|---|---|
| B (결함 확실) | **1** | 눈 감김 1장 (PHB_7670). 흔들림·초점·노출은 0장 |
| OK (정상) | 116 | |
| OK_EXPR (표정 주의) | 21 | 눈을 가늘게 뜬 웃음 등. 이 중 3장은 최종 선택(별점 5) |
| UNSURE (애매) | 7 | 집계 제외 |

B가 1장이라 **정탐률(찾아야 할 결함을 찾아낸 비율)은 이 행사로 의미 있게 잴 수 없다.** 결함이 거의 없는 행사라는 것이 사실이므로 라벨링이 틀린 것이 아니다.

### 이 행사로 이미 잴 수 있는 것

| 지표 | 가능 | 방법 |
|---|---|---|
| **오탐률** (좋은 컷이 걸림) | **가능, 이 행사가 오히려 좋음** | 정상 116 + 표정 주의 21 + 최종 선택 16장 중 후보로 걸린 개수. 표정 주의 21장이 가장 어려운 시험이다 |
| 판정 불가 비율 | 가능 | 옆모습, 작은 얼굴 등 |
| 처리 시간 | 가능 (145장) | |
| **정탐률** | **불가** (B 1장) | 아래 방법이 필요 |

**표본 기준과 비교 (3장 기준)**
- **눈 감김:** 정답 B **48장**으로 기준(30장 이상)을 넘었다. **눈 감김 정탐률은 의미 있는 값으로 보고할 수 있다.**
- **흔들림·초점·노출:** 실제 결함 **0장**이라 기준(사유별 20장 이상)에 전혀 못 미친다. **이 세 사유의 정탐률은 합성 열화(방법 B)로만 잴 수 있고, 실제 행사 정탐률은 "미측정"이다.**
- **오탐 시험:** 표정 주의 84장(최종 선택 3장 포함)은 오탐 시험에 매우 좋은 표본이다.

**확인이 필요한 점:** 망원 렌즈로 움직이는 인물을 찍은 행사인데 흔들림·초점 실패가 0장이다. 실제로 없었는지, 이 행사에서 결함을 눈 감김 한 가지로 표시했는지 사용자 확인이 필요하다. 후자라면 라벨을 고쳐야 한다.

## 2. 방법 선택 (연출 촬영은 쓰지 않는다)

| 방법 | 설명 | 채택 | 정답 신뢰도 |
|---|---|---|---|
| ~~A. 연출 촬영~~ | 일부러 결함을 찍는 방법 | **제외** (사용자 결정) | - |
| **B. 합성 열화 (페어)** | 깨끗한 사진에 흔들림·흐림·노출 열화를 컴퓨터로 입힌다 | **채택** (개발 중 경향 확인) | 중간 |
| **C. 다른 행사의 자연 결함** | 컷 전 원본 폴더에서 실제 결함 컷을 표시한다 | **채택** (**최종 판정은 여기서**) | **가장 높음** |
| D. 공개 데이터셋 (눈 감김) | 눈 감은 얼굴 공개 데이터를 쓴다 | **보류.** C로 눈 감김 표본이 부족할 때만, 사용자 허락 후 | 중간 |

### 연출 촬영을 뺀 결과로 달라지는 것 (중요)

| 사유 | 측정 가능한 방법 | 의미 |
|---|---|---|
| 흔들림, 초점 실패(전체/얼굴), 노출 | **B + C** | 합성으로 경향을 보고, 실제 행사로 확인 |
| **눈 감김** | **C만** (D는 보류) | **합성하지 않는다** (부자연스러움). 즉 **눈 감김 정탐률은 다른 행사 사진이 없으면 잴 수 없다** |

**눈 감김은 raw_problem.md에서 가장 대표적인 B컷 사유**로 언급된 것이라 이 제약이 가장 아프다. 그래서 방법 C(다른 행사)가 선택이 아니라 **필수**가 된다.

**다른 행사 사진을 구하지 못할 때의 대응:**
- 눈 감김 정탐률은 **"미측정"으로 보고한다.** 숫자를 지어내지 않는다.
- 이 경우 도구의 눈 감김 판정은 확정 제외 용도로 쓰지 않고, **참고 표시만** 한다 (PRD 설계 원칙, CUJ-03 E3).
- 오탐률(표정 주의 21장 등)은 이 행사로 이미 측정할 수 있으므로, 최소한 "잘못 걸러내지 않는다"는 것은 확인된다.

## 3. 방법 C: 다른 행사의 자연 결함 (최종 판정용)

### 구할 사진

| 항목 | 기준 **[제안]** | 이유 |
|---|---|---|
| **컷 전 원본** | 셀렉하기 전 상태 (연사, 실패 컷이 그대로 남은 폴더) | 이 행사처럼 이미 걸러진 폴더는 결함이 없다 |
| 규모 | 중 (약 700~1000장) 1건 이상, 가능하면 대 (약 1200~1500장) 1건 | PRD·S1 검증 계획의 소·중·대 구분 |
| 내용 | **인물 위주** 행사 (눈 감김이 나오려면 연사로 찍은 인물 컷이 많아야 함) | |
| 포맷 | CR3 등 RAW 또는 JPEG | `sips`가 CR3를 읽는 것을 확인함 |
| 위치 | 이 MacBook (외장 디스크 가능) | 사진은 외부로 보내지 않는다 |

### 표본 크기 기준 **[제안]**

| 사유 | 정탐률을 "의미 있다"고 보고하려면 | 못 미치면 |
|---|---|---|
| 눈 감김 | 정답 B가 **30장 이상** | "참고치"로 표시. 합격 판정에 쓰지 않는다 |
| 흔들림, 초점, 노출 | 사유별 **20장 이상** (B와 합쳐서 판단) | 합성(B)이 보완 |

표본이 적으면 정탐률의 오차가 크다 (예: 30장에서 70% = 21장, 오차 약 ±16%p **[대략의 추정]**).

### 라벨링 방식

[labeling-guide.md](labeling-guide.md) 4장과 같은 방법을 쓴다 (새 카탈로그에서 컬러 태그, 확신 있을 때만 B, 애매는 보라). 1000장 이상이면 시간이 길어지므로:

- **연속 촬영 구간 약 400장**을 골라 그 구간만 라벨링한다 **[제안]**. 전체에서 무작위로 고르면 연사(눈 감김이 나오는 곳)가 흩어져 오히려 비효율적이다.
- 구간 선택은 **결함이 있을 것 같은 곳을 골라서 하지 않는다.** (골라서 하면 정탐률이 부풀려진다.) 시간 순서로 연속된 구간 또는 무작위 시작점.
- 100% 확대 확인은 이 행사처럼 전체에 한다. 건너뛰면 "정상" 속에 숨은 결함이 섞인다.

## 4. 방법 B: 합성 열화 (페어 설계, 개발 중 경향 확인용)

### 설계

- 원본 사진 N장(`OK` 라벨)에서 **같은 사진을 열화한 버전**을 만든다. 원본은 음성(결함 없음), 열화본은 양성(결함)으로 짝을 짓는다.
- 같은 사진이라 **오탐도 동시에 잰다.** 원본이 걸리면 오탐, 열화본이 안 걸리면 미탐.
- 원본(CR3)은 수정하지 않는다. `sips`로 읽어서 JPEG(1600px 폭 등)로 만든 **복사본에만** 열화를 입힌다.

### 대상 사진 **[제안]**

OK 라벨 20장. 얼굴이 크게 보이는 컷 10장 + 제품·얼굴 없는 컷 10장. 표정 주의(OK_EXPR)는 열화 대상에서 빼고 오탐 시험에만 쓴다.

### 열화 종류와 단계 **[제안, 값은 사람 판단으로 조정]**

| 사유 | 열화 방법 | 단계 | 비고 |
|---|---|---|---|
| 흔들림 | 직선 모션 블러 | 4단계 (약함 → 심함) | 방향은 무작위 |
| 초점 실패 (전체 흐림) | 가우시안 블러 | 4단계 | |
| 초점 실패 (얼굴 영역만) | **얼굴 영역만** 블러, 배경은 선명 유지 | 4단계 | 후핀 시뮬레이션. 얼굴 위치가 필요해서 T1.3(얼굴 검출) 이후 가능 |
| 노출 | 과노출·저노출 (밝기 이동) | ±1, ±2, ±3 단계 | |
| 눈 감김 | **합성하지 않는다** | - | 방법 C로만 (위 2장) |

규모: 20장 × (흔들림 4 + 전체 블러 4 + 얼굴 블러 4 + 노출 6) = 열화본 약 360장 + 원본 20장.

### "명백한 B컷" 기준선 정하기 (사람 지각 테스트)

도구가 어느 단계부터 잡아야 하는지는 **사람이 정한다.** 정하지 않으면 정탐률 숫자가 무의미하다.

1. 각 열화 종류에서 대표 사진 2장씩, 단계 1~4를 한 줄로 나열해 보여 준다 (제가 만든다).
2. 사용자가 "행사에서 **이 단계부터는 바로 버린다**"를 고른다. 이것이 기준 단계 L*이다.
3. L* 이상 단계를 "명백한 B컷"으로 간주해 정탐률을 계산하고, L* 미만은 "애매"로 집계에서 뺀다.

소요: 약 15분 (사용자, T0.6a).

## 5. 결과 보고 형식

사유별 × 단계별 표로 낸다. **한 숫자(정탐률 x%)로 뭉치지 않는다.** 어디서 약한지가 보여야 개선할 수 있다.

| 사유 | 단계 1 | 단계 2 | 단계 3 | 단계 4 | L* 이상 정탐률 (B) | 실제 행사 정탐률 (C) |
|---|---|---|---|---|---|---|
| 흔들림 | % | % | % | % | % | % (표본 n장) |
| 전체 흐림 | | | | | | |
| 얼굴 흐림 | | | | | | |
| 노출 | | | | | | |
| 눈 감김 | - | - | - | - | **합성 안 함** | % (표본 n장, 없으면 "미측정") |

오탐 열: 원본 20장, 정상 116장, 표정 주의 21장(특히 최종 선택 3장) 중 걸린 개수.

### 해석 규칙

- 정탐률 합격 기준은 기존 제안과 같다: **50% 이상이면 의미 있음, 70% 이상이면 우수 [제안, 본인 확정 필요]**. 단, L* 이상 단계에서만 센다.
- **오탐은 어느 방법에서든 0에 가까워야 한다.** 정탐률이 높아도 오탐이 나면 불합격이다 (C5).
- **합성(B)의 수치는 "경향"** 으로만 쓴다. **합격 판정은 C(실제 행사)** 로 한다. C가 없으면 해당 사유는 "미측정"이다.

## 6. 한계

1. **합성은 실제 결함과 다르다.** 실제 흔들림은 노이즈, 비선형 번짐, 일부만 흐린 형태가 섞인다. 합성 결과가 좋아도 실제 행사에서 낮을 수 있다. 반대도 가능하다.
2. **눈 감김은 합성도 연출도 없다.** 표본은 오직 다른 행사 사진에 달려 있다. 이 계획의 가장 큰 의존성이다.
3. **`sips` 변환본으로 평가하면 RAW 직접 판독과 다를 수 있다.** 현상(톤, 샤프닝)이 적용된 JPEG이기 때문이다. Phase 1에서 어떤 입력(RAW 프리뷰, 현상본)을 쓸지 정한 뒤, 평가도 같은 입력으로 한다.
4. **합성의 정상 원본은 이 행사 하나뿐**이라 다양성이 낮다. 다른 행사 사진이 생기면 거기서도 원본을 골라 늘린다.
5. 다른 행사 사진의 라벨링은 사용자 시간이 든다. 구간 선택(400장)으로 줄이되, 표본이 적어질 수 있다.

## 7. CR3 읽기 확인 결과 (devplan T1.2에 반영)

macOS 기본 도구 `sips`로 CR3를 읽을 수 있다 (2026-10-19, 1장 시험, 원본은 수정하지 않음).

| 변환 | 결과 | 시간 (1장) |
|---|---|---|
| 풀 사이즈 JPEG | 8192×5464, 약 7.6 MB | 약 2.9초 |
| 폭 1600px JPEG | 약 196 KB | 약 1.2초 |

- **1500장이면 1600px 변환만 약 30분 (1장 기준 추정, 단일 처리)** 이다. 병렬 처리하면 줄 수 있고, 내장 프리뷰를 읽으면 더 빠를 수 있다. 정확한 수치는 T1.2에서 여러 장으로 다시 측정한다.
- 설치된 Python(3.13, 3.14)에는 Pillow가 있지만, 격리 모드로 실행했을 때는 못 찾았다. 개발용 가상환경에서 설치하면 된다 (T1.1).
- `exiftool`은 설치되어 있지 않다. 내장 프리뷰 추출이 필요하면 별도 설치가 필요하다 (T1.2에서 판단).

## 10. 확정된 평가 설계 (두 행사 라벨 반영, 2026-10-19)

### 10-1. 데이터셋

### 10-2. 눈 감김: 보정과 평가를 분리하는 방법

E2의 B 47장은 **25개의 연사 묶음**에 모여 있고, 그중 한 묶음이 **연속 14장**이다 (47장의 30%). 즉 독립적인 표본은 47이 아니라 **약 25개**다. 같은 연사 안의 컷은 서로 거의 같아서, 무작위로 장 단위로 나누면 보정에 쓴 컷과 거의 같은 컷으로 평가하게 된다 (누수).

| 방식 | 내용 |
|---|---|
| **구간(블록) 단위 교차 검증** | E2를 시간순으로 100장씩 4블록으로 나눈다. 3블록으로 보정하고 남은 1블록으로 평가하기를 4번 돌린다 |
| 블록별 B 장수 | 5 / 11 / 10 / 21 (블록 4가 가장 많고, 14장 연속 묶음이 있는 블록과 겹칠 수 있음) |
| 보고 | 4번의 평가 결과를 **각각** 보여 주고, 평균은 참고로만 쓴다 |
| 경계 | 블록 경계에서 연사가 잘릴 수 있다. 경계에 걸친 묶음은 같은 블록에 두는 쪽으로 경계를 조정한다 |

### 10-3. 정탐률은 두 가지로 보고한다

| 지표 | 정의 | 이유 |
|---|---|---|
| **장 단위 정탐률** | 정답 B 47장 중 도구가 후보로 잡은 비율 | 기존 정의 |
| **묶음 단위 정탐률** | 25개 묶음 중 **묶음 안에 후보로 잡힌 컷이 하나라도 있는** 비율 | 연사에서 눈 감은 컷을 하나라도 걸러 주면 사용자가 그 묶음을 확인하게 된다. 14장 묶음 하나가 장 단위 숫자를 좌우하는 것을 막아 준다 |

### 10-4. 합격 기준

| 사유 | 평가 방법 | 기준 **[제안, 본인 확정 필요]** |
|---|---|---|
| **눈 감김 정탐률** | E2 블록 교차 검증 → 최종은 H | 50% 이상 의미 있음, 70% 이상 우수 (장·묶음 단위 모두 보고) |
| **오탐 (모든 사유)** | E1 + E2의 OK·OK_EXPR·최종 선택 | 0에 가깝게 (대형 행사 1건에서 최종 선택 컷이 한두 장 이내). **표정 주의 84장에서 걸리는 개수를 따로 보고** |
| 흔들림·초점·노출 정탐률 | **S(합성)로 경향만.** 실제 행사 정탐률은 **"미측정"** | 합성에서 L* 이상 단계 70% 이상은 참고 목표일 뿐, **합격 판정에 쓰지 않는다** |
| 흔들림·초점·노출 **오탐** | E1+E2의 정상·표정 주의 약 487장 (실제로 흔들림·초점 결함이 없는 컷들) | **실제로 결함이 없는 컷에서 후보로 걸리면 오탐.** 이 487장은 해당 사유의 가장 좋은 음성 표본이다 |

> 흔들림·초점 결함이 실제로 0장이라는 것은, 이 사용자의 이 두 행사에서는 이 결함이 드물다는 뜻이다. 반대로 이 판정기가 정상 컷을 잘못 걸러 내는 위험은 지금 데이터로 이미 측정할 수 있다.

### 10-5. 이 결과가 제품 범위에 주는 시사점 (결정 필요)

| 관찰 | 의미 |
|---|---|
| 두 행사의 실제 B 48장 중 **47장이 눈 감김, 흔들림·초점·노출은 0장** | 이 사용자의 워크플로에서는 **눈 감김이 사실상 유일한 기술적 결함**일 수 있다 (표본은 2개 행사뿐) |
| raw_problem에서는 "눈 감김, 초점 실패, 흔들림"을 같이 예로 들었다 | 사용자의 인식과 데이터가 다르다. 흔들림·초점 컷은 애초에 걸러서 찍거나 현장에서 지우고 올 가능성이 있다 [가정] |

**제안 [결정 필요 D9]:** v1의 개발 순서를 **눈 감김 우선**으로 한다.
1. 눈 감김 판정(T1.4)과 판정 불가 분리(T1.5), 표정 주의 오탐 억제를 먼저 완성하고 평가한다.
2. 흔들림·초점·노출 판정은 **그 뒤에** 만든다. 실제 결함이 거의 없다는 것이 확인됐으므로 우선순위가 낮다 (Should 유지 또는 Could로 하향).
3. 만들더라도 **오탐 억제가 목표**다. 정탐률은 합성으로만 보고하고 "참고 표시"로 운영한다.

이 순서로 하면 Phase 1이 짧아지고, 가장 가치가 높은 부분(눈 감김)에 시간을 쓸 수 있다.
