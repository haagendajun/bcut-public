# T1.2 스파이크 결과: CR3를 어떻게 읽을 것인가

> 실행일: 2026-10-19 · 가벼운 버전(표본 30장 + 두 행사 545장 존재 확인). 400장 병렬 처리량은 측정하지 않았다.
> 코드: [tools/spike_t12_image_reading.py](../tools/spike_t12_image_reading.py) (스파이크 전용 가상환경에서 실행, 프로젝트 의존성 아님)
> 표본: EVENT_A 구간에서 눈 감김 10장, 표정 주의 10장, 정상 10장 (시드 12). 사진은 읽기만 했고 사람이 열어 보지 않았다.

## 1. 결론

**기본 입력으로 "CR3 내장 원본 크기 JPEG"를 쓴다.** 카메라가 CR3 안에 넣어 둔 8192×5464 JPEG를 `rawpy.extract_thumb()`로 꺼내서 읽는다.

| | `sips` (RAW 디코딩) | **내장 원본 JPEG (채택)** |
|---|---|---|
| 1장당 시간 (폭 1600 결과까지) | 1164 ms | **75 ms** (draft 2048) |
| 1500장 추정 (단일 처리) | 약 29분 | **약 2분** |
| 선명도 순위 일치도 (기준 대비) | 기준 | **0.967** |

545장 전부(EVENT_B 145 + EVENT_A 400)에 8192×5464 JPEG가 들어 있었고, 꺼내기에 실패한 파일은 0건이다.

## 2. 측정 결과

### 2-1. 시간 (1장, 표본 30장 중앙값, 디스크 캐시를 데운 뒤)

| 방법 | 중앙값 | p90 | 비고 |
|---|---|---|---|
| M0 `sips` 1600 (RAW 디코딩, **기준**) | 1164 ms | 1186 ms | 지금까지 쓰던 방식 |
| M1 내장 원본 JPEG 풀 디코딩 + 1600 축소 | 393 ms | 401 ms | |
| **M2 내장 원본 JPEG, draft 2048 → 1600** | **75 ms** | 84 ms | **채택** |
| M3 내장 원본 JPEG, draft 1024 → 1600 확대 | 54 ms | 61 ms | 선명도 값이 크게 달라짐 |
| M4 내장 미리보기 1620×1080 → 1600 | 28 ms | 28 ms | 가장 빠르지만 해상도가 낮음 |
| M5 rawpy `half_size` 4096 → 1600 | 711 ms | 719 ms | 탈락 (아래) |
| rawpy 풀 디코딩 (3장) | 1.88 s | | 참고 |

**내장 원본 JPEG의 디코딩 해상도별 시간 (중앙값, 10장):** 1024px 34 ms · 2048px 43 ms · 4096px 51 ms · **8192px 77 ms**. 풀 해상도로 읽어도 77 ms라서, 눈이나 얼굴 영역을 **잘라서 정밀하게 볼 때도 부담이 없다.**

### 2-2. 충실도: 기준(M0) 대비 (표본 30장)

| 방법 | 선명도 순위상관 (전체 / 중앙) | 선명도 값 비율 | 평균 밝기 차 | 하이라이트·섀도 클리핑 차 |
|---|---|---|---|---|
| M1 풀 디코딩 | 0.971 / 0.909 | 1.42× | +0.6 | -0.12%p / -0.92%p |
| **M2 draft 2048** | **0.967 / 0.809** | 1.16× | +0.6 | -0.13%p / -0.93%p |
| M3 draft 1024 | 0.955 / 0.959 | 0.46× | +0.7 | -0.13%p / -0.92%p |
| M4 미리보기 1620 | 0.974 / 0.931 | 0.69× | +0.6 | -0.18%p / -0.92%p |
| M5 rawpy half_size | **-0.205** / -0.204 | 0.44× | **-32.7 (최대 56)** | **-5.37%p** / -0.26%p |

해석:
- **내장 JPEG(M1~M4)는 서로 순위가 거의 같다** (0.95~0.97). 어떤 사진이 더 흐린지 판단하는 데는 어느 것을 써도 비슷하다.
- **밝기와 클리핑은 내장 JPEG가 `sips`와 거의 같다** (평균 밝기 차 0.6 이내, 클리핑 차 1%p 이내). 노출 판정에 쓸 수 있다.
- **선명도의 "값 자체"는 방법마다 크게 다르다** (0.44배에서 1.42배). 그래서 아래 3번 규칙이 필요하다.
- **M5(rawpy 직접 현상)는 탈락:** 밝기가 평균 33이나 어둡게 나오고, 선명도 순위가 오히려 반대 방향(-0.2)이다. 현상 설정(톤 곡선 등)이 `sips`와 달라서 생긴 차이로 보이며, 원인은 확인하지 않았다 [미확인]. 어차피 711 ms로 느리다.

## 3. 이 결과로 정한 것

1. **기본 입력 = CR3 내장 원본 JPEG** (`rawpy.extract_thumb`). 8192×5464를 필요에 맞게 읽는다.
   - **전역 분석(노출, 전체 선명도, 얼굴 위치 찾기):** draft 2048로 읽는다 (약 43 ms).
   - **눈·얼굴 영역 정밀 분석:** 2048에서 찾은 위치를 풀 해상도(8192, 약 77 ms)에서 잘라 쓴다. 필요한 만큼의 해상도는 T1.3(얼굴 검출)에서 정한다.
   - **리포트 썸네일(T1.18):** 같은 JPEG를 draft 1024로 읽어 줄인다 (약 34 ms).
2. **폴백(내장 JPEG가 없거나 읽기 실패할 때):** `sips` 1600으로 읽고, 그 컷은 리포트에 "대체 경로로 읽음"으로 표시한다. JPEG 입력 파일은 그대로 읽는다. 지금 확인된 범위(Canon EOS R5, 545장)에서는 폴백이 필요한 파일이 0건이다.
3. **임계값은 입력 경로에 묶인다.** 선명도 값이 경로마다 달라서, **한 경로로 보정(calibrate)하고 평가한 임계값은 다른 경로에서 쓸 수 없다.** 폴백 경로로 읽은 컷은 임계값이 안 맞을 수 있으므로 `review` 등급으로 보낸다 [제안].
4. `sips`는 **기준값 비교와 폴백 용도로만** 남긴다.

## 4. 한계와 위험

| # | 내용 | 영향 |
|---|---|---|
| 1 | **기준(M0)은 정답이 아니라 `sips`의 현상 결과다.** 내장 JPEG가 `sips`와 같다는 것이지, Capture One 화면과 같다는 뜻은 아니다 | 노출 판정(T1.17)은 사용자 눈에 보이는 밝기와 맞는지 정상·표정 주의 컷으로 따로 확인한다 |
| 2 | **내장 JPEG는 카메라 안에서 현상된 것**(픽처 스타일, 샤프닝, 노이즈 처리)이다. 사용자가 Capture One에서 바꾼 설정은 반영되지 않는다 | 판정은 "촬영된 그대로"를 본다. 현상 후 상태가 아니다 |
| 3 | **표본이 30장**이고 카메라는 Canon EOS R5 한 대뿐이다 | 다른 카메라는 내장 JPEG 크기·유무가 다를 수 있다 (폴백으로 대응) |
| 4 | **병렬 처리량은 측정하지 않았다** (가벼운 버전) | 1500장 약 2분은 단일 처리 추정치다. 병렬이면 줄 것으로 예상하지만 미검증 |
| 5 | `rawpy`(내부적으로 LibRaw) 라이선스를 확인하지 않았다 | **[미확인]** 프로젝트 의존성으로 넣기 전에 확인한다 |
| 6 | 선명도 순위 일치도가 중앙부 기준으로는 0.81(M2)까지 내려간다 | 눈 영역만 보는 판정은 풀 해상도 crop에서 새로 측정한다 (T1.3~1.6) |
