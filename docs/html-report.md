## 1. 쓰는 법

```bash
~/.venvs/photo-select/bin/bcut scan --folder "<행사 폴더>" --out "<결과를 쓸 폴더>"
```

그 다음 결과 폴더의 **`bcut-report.html`** 을 더블클릭하면 브라우저에서 열린다.

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--folder` | 필수 | 행사 폴더. 사진(CR3)을 **읽기만** 한다 |
| `--out` | `bcut-out/<행사 폴더 이름>/` | 결과 폴더. **행사 폴더 안이면 거부한다** |
| `--thumbs` | `all` | `all` = 모든 컷에 썸네일, `flagged` = 후보·확인·판정 불가만 (파일이 훨씬 작아진다) |
| `--thumb-width` | 320 | 썸네일 폭(px) |
| `--workers` | 최대 6 | 동시에 처리하는 개수 |

실제 사용 예 (이 프로젝트의 두 행사):

```bash
~/.venvs/photo-select/bin/bcut scan \
  --folder ~/photo-select-data/events/260223_EVENT_A_seg400 \
  --out ~/photo-select-data/reports/260223_EVENT_A_seg400
```

**결과 폴더는 iCloud에 동기화되지 않는 곳(예: `~/photo-select-data/reports/`)에 두는 것을 권한다.** 프로젝트 폴더(바탕화면)는 iCloud와 동기화되고, HTML에는 사진 썸네일이 들어 있다.

## 2. 화면

| 영역 | 내용 |
|---|---|
| 요약 카드 | 등급별(B컷 후보, 사람이 확인, 정상, 얼굴 없음·판정 불가)과 **사유별(눈 감김으로 올라온 컷, 노출로 올라온 컷)** 장수 |
| 맨 위 | **제목: `<행사 이름> · 1차 컷 리포트`** (브라우저 탭에서 행사를 구분할 수 있다). 부제목: 판정 범위(`눈 감김 판정`), 사진 수, 만든 시각, 판정 기준(후보 ≤ 0.134, 확인 ≤ 0.162, 눈 폭 비율). 개인정보 안내 |
| 요약 카드 | B컷 후보 / 사람이 확인 / 정상 / 얼굴 없음·판정 불가 장수 |
| 등급 필터 | 후보+확인(기본) / B컷 후보 / 사람이 확인 / 정상 / 얼굴 없음·판정 불가 / 전체 |
| **판정 종류 필터** | **눈 감김 / 노출** (장수 표시). 한 번 더 누르면 해제. 등급 필터와 함께 쓸 수 있다 (예: "노출 + 사람이 확인"). 두 사유가 함께 걸린 사진은 두 필터 모두에 나온다 |
| 세부 사유 필터 | 눈이 좁음, 단체 사진, 읽기 실패 (해당하는 컷이 있을 때만 보인다). 한 번 더 누르면 해제 |
| 정렬 | **가장 감긴 순**(눈 점수 낮은 순, 기본) / **노출 이상이 심한 순** / 파일 이름순 / 얼굴 많은 순 |
| 썸네일 크기 | 슬라이더 (110~320px) |
| 컷 카드 | 썸네일(판정에 쓴 얼굴에 상자: 빨강 후보, 주황 확인, 초록 정상, 굵은 상자가 등급을 정한 얼굴), 파일 이름, 등급 배지, **사유 배지(눈 감김, 노출: 얼굴이 하얗게 날아감/사진이 하얗게 날아감/너무 어두움)**, 세부 사유 배지, 눈 점수, 얼굴 수(판정에 쓴 얼굴 수). 노출로 걸린 컷은 **상위 1% 밝기와 날아간 비율**도 보인다 |
| 살리기 | 컷마다 버튼. 누르면 흐리게 표시되고 **브라우저 안에만 기억한다.** 같은 파일을 다시 열면 이어서 보인다 |
| 이름 저장 | "살린 컷 이름 저장"(`bcut-saved.txt`), "보이는 컷 이름 저장"(`bcut-visible.txt`). 파일 이름을 줄마다 적은 텍스트 |

점수는 **두 눈 중 덜 감긴 쪽 눈의 열림 비율**이다 (낮을수록 감김).

**이름을 "1차 컷 리포트"로 한 이유 (2026-10-19 결정):** 이 도구는 A컷을 고르지 않고 눈 감김 같은 명백한 B컷만 걸러 낸다. "정상"은 결함이 없다는 뜻이지 A컷이라는 뜻이 아니다. 그래서 "A컷 판정"이나 "B컷 후보 리포트"(정상 컷도 들어 있어 맞지 않음)가 아니라, 업무에서 쓰던 "1차 컷" 단계 이름을 쓴다. 화면 맨 아래에도 "정상은 A컷이라는 뜻이 아니고, 좋은 컷을 고르는 일은 사람이 한다"고 적어 두었다. 흔들림·초점·노출 판정이 들어오면 부제목의 판정 범위만 늘린다.

## 3. 안전하게 만든 부분

| 약속 | 어떻게 지켰나 | 확인 |
|---|---|---|
| 사진은 외부로 나가지 않는다 (C1) | HTML은 **외부 주소를 하나도 쓰지 않는다** (글꼴, 스크립트, 이미지, 요청 모두 파일 안). 서버도 없다 | 테스트가 `http://`, `https://`, `<link`, `<script src`, `fetch(`, `XMLHttpRequest`, `WebSocket`, `url(` 등이 없는지 검사 |
| 행사 폴더는 읽기만 한다 | 결과는 `--out` 폴더에만 쓰고, 행사 폴더 안(같은 폴더, 하위, `..`로 들어오는 경로)이면 거부한다 | 테스트로 실행 전후 파일 이름·크기·수정시각 동일, 실제 사진 545장 스캔 전후 폴더 지문도 동일 |
| 사진을 삭제하지 않는다 (C3) | 삭제 호출이 없다 (기존 코드 검사 테스트가 이 모듈도 대상) | 테스트 통과 |
| 파일 이름이 코드로 해석되지 않는다 | 이름은 데이터 블록에 `<`를 이스케이프해서 넣고, 화면에는 `textContent`로만 표시한다 (`innerHTML` 없음) | 악성 이름(`</script><img onerror=...>`) 테스트 |
| "살리기"는 파일에 쓰지 않는다 | 브라우저 `localStorage`에만 저장한다 | 화면 코드 실행 테스트 |
| 손상된 사진이 전체를 멈추지 않는다 | 그 컷을 "사람이 확인"(`read_error`)으로 보낸다 | 테스트 |

## 4. 어떻게 검증했나

브라우저 창에서 파일을 직접 열 수는 없었다 (접근이 허용되지 않았다). 대신 **macOS의 자바스크립트 엔진(JavaScriptCore)으로 화면 코드를 실제 실행**하는 테스트를 만들었다. 아주 작은 가짜 화면(DOM) 환경에서 필터, 정렬, 살리기, 저장, 이름 목록 내려받기, 썸네일 크기 조절을 모두 눌러 보고 결과를 확인한다 (테스트 14개). 실제 EVENT_A·EVENT_B 리포트도 같은 방법으로 오류 없이 실행되고, 필터별 장수가 요약 카드와 일치함을 확인했다.

**아직 사람이 브라우저에서 눈으로 본 확인은 없다.** 레이아웃(간격, 글자 크기, 어두운 화면 색)은 코드로 검증하지 못했으므로 열어 보고 불편한 점을 알려 주면 고친다.

## 7. 노출 연결 (2026-10-19)

| 항목 | 내용 |
|---|---|
| 등급 합치기 | 사진의 등급은 사유별 등급 중 높은 것이다. 눈 감김이 후보면 후보, 눈 감김이 확인이거나 **노출이 걸리면 확인**, 아니면 눈 감김 판정의 등급(정상·얼굴 없음·판정 불가). 노출은 v1에서 **사람이 확인 전용**이라 노출만으로는 후보가 되지 않는다 |
| CSV | `reason` 열에 걸린 사유가 들어간다 (`eyes_closed`, `exposure`, 둘 다면 `eyes_closed;exposure`). 열이 4개 늘었다: `exposure`(이유), `exposure_p99`(상위 1% 밝기), `exposure_face_hi`(얼굴 날아간 비율), `exposure_global_hi`(사진 전체 날아간 비율) |
| CLI | 실행 결과에 **사유별 장수**가 나온다 (눈 감김 N장, 노출 N장, 둘 다 M장) |
| 회귀 점검 | 실제 두 행사에서 연결 전후를 비교했다: **EVENT_A 400장, EVENT_B 145장 모두 등급·사유·점수가 달라진 컷 0장**, 노출로 걸린 컷 0장 (앞선 평가와 같다), 행사 폴더 지문도 전후 같다 |
| 속도 | 400장 7.2초 (18 ms/장), 145장 2.9초 (20 ms/장). 노출 판정을 넣기 전과 거의 같다 |

### 데모 리포트

실제 사진에는 노출 이상이 없어서(0장) 리포트의 노출 화면을 볼 수 없다. 그래서 **실제 사진 일부의 노출을 인위적으로 바꾼 상태로 판정한 데모 리포트**를 만들었다 (`eval/make_exposure_demo.py`).

- 위치: `~/photo-select-data/reports/exposure-demo/bcut-report.html` (iCloud에 동기화되지 않는 폴더)
- 제목에 **[데모]** 가 붙어 있고, 노출 결함이 실제가 아니라 인위적으로 바꾼 것임을 부제목에 적었다.
- 34장 중 28장의 노출을 -3~+3단계로 바꿨다. 노출이 바뀐 28장 중 22장이 노출로 걸렸고, **바꾸지 않은 원본 6장 중 걸린 것은 0장**이다. 가벼운 변화(-2단계 4장 모두, +1단계 일부)는 일부러 잡지 않는다.
