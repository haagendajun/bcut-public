# Capture One AppleScript 가능성 (T0.5)

작성: 2026-10-19 (초안). 대상: Capture One **16.7.1.11**(이 MacBook), 스크립트 사전 `/Applications/Capture One.app/Contents/Resources/CaptureOne.sdef`.
**이 문서의 "사전에서 읽은 것"은 사전 파일만 읽은 결과이고, 실제로 동작하는지는 아직 시험하지 않았다.** 시험 결과는 3장에 채운다.

## 1. 사전에서 읽은 것 (정적 분석, 미검증)

| 시험 | 사전의 근거 | 전망 |
|---|---|---|
| 1 변형을 파일명으로 찾기 | `image`에 `name`(파일명), `path`(원본 전체 경로), `id`; `image`가 `variant`를 가진다 | 가능해 보임. 경로로 찾는 것이 더 안전 |
| 2 별점 읽기/쓰기 | `variant`의 `rating`(정수, 읽기·쓰기) | 가능해 보임 |
| 3 컬러 태그 읽기/쓰기 | `variant`의 `color tag`(정수, 읽기·쓰기) | 가능해 보임 |
| 4 **키워드 추가/제거** | `keyword`(이름·부모는 읽기 전용), `apply keyword`(**이미 있는 키워드**를 변형 여러 개에 적용). `variant`와 `document`가 `keyword`를 요소로 가짐. 일반 `make`/`delete` 명령이 있음 | **추가는 가능성이 높다.** 단 키워드를 먼저 만들 수 있는지(`make new keyword`), **제거**를 어떻게 하는지(`delete keyword of variant`?)는 사전만으로 알 수 없다 → 시험 필요 |
| 5 스마트 앨범 생성 | `collection`의 `kind`에 `smart album`이 있지만 `rules`는 **읽기 전용** | **스크립트로 규칙을 지정해 만들 수 없을 가능성이 높다.** 대안: 사람이 스마트 앨범을 한 번 만들게 하는 안내(T2.6), 또는 일반 앨범을 만들고 `add inside`로 사진을 넣기 |
| 6 일괄 적용 속도 | `apply keyword`가 변형 목록을 한 번에 받는다 | 반복 호출보다 빠를 것으로 기대. 시험 필요 |
| 7 사용자 수정 구분 | 변경 이력·수정 시각 속성은 못 찾음 | 반영 직전 값을 우리가 저장해 두고 비교하는 방식이 필요할 가능성 (Q5) |

## 2. 덤으로 알게 된 것

- `backup now`(문서 백업을 스크립트로 실행), `relink`(이미지 파일 경로 다시 연결)이 있다. 백업은 `apply` 전에 자동으로 하는 안전장치로 쓸 수 있고, `relink`는 경로가 바뀐 `PILOT2` 카탈로그를 다시 잇는 데 쓸 수 있다.
- `synchronize`(폴더 컬렉션 동기화), `add inside`(앨범에 변형 추가), `select`/`deselect`가 있다.
- `silently quit`, `exists`, `count`가 있어 스크립트에서 상태를 확인하기 쉽다.

## 3. 시험 결과 (2026-10-19, 시험용 카탈로그 `bcut-test`, 사진 20장)

| 시험 | 결과 | 사용한 문법 | 비고 |
|---|---|---|---|
| 1 파일명으로 찾기 | **성공** | `every image of doc whose name is "PHA_8003.CR3"` → 1개. `path of image`로 전체 경로도 읽힘 | 변형은 `variant 1 of image` |
| 2 별점 읽기/쓰기 | **성공** | `rating of v`, `set rating of v to 3`, 원래 값으로 복구 확인 | 기본값 0 |
| 3 컬러 태그 읽기/쓰기 | **성공** | `color tag of v` (정수), `set color tag of v to 2`, 복구 확인 | 기본값 0 |
| 4 키워드 | **성공 (조건 있음)** | 읽기 `name of every keyword of v`. **새 키워드 만들기는 모두 실패**(`make new keyword ... with properties {name:}`, `with data`, 이름만으로 만들기, `apply keyword "텍스트"`). 사람이 키워드 도구에서 만든 `bcut-test-kw`는 `keyword "bcut-test-kw" of doc`로 찾아 **`apply keyword kw to {variants}`로 적용 성공**, **`delete (keyword "bcut-test-kw" of v)`로 제거 성공**(화면에서 사라짐, 같은 사진의 다른 키워드는 건드리지 않음) | **조건 1: 키워드는 사람이 카탈로그마다 한 번 만들어야 한다.** **조건 2: 제거 후 스크립트 읽기가 틀린다.** 제거한 변형이 `개수 1, 이름 missing value`로 읽힌다(유령). 이름이 `missing value`인 항목은 없는 것으로 취급해야 한다. 이미 제거한 키워드를 다시 지우면 "가져올 수 없다" 오류가 나므로 오류는 "이미 없음"으로 처리 가능 |
| 5 스마트 앨범 | **성공** | 사람이 만든 키워드 조건 스마트 앨범의 `rules`를 읽어 **형식을 알아냈다**(XML): `<?xml version="1.0"?><MatchOperator Kind="AND"><MatchOperator Kind="AND"><Condition Enabled="YES"><Key>IB_S_CONTENT_KEYWORDS</Key><Operator>0</Operator><Criterion>bcut-test-kw</Criterion></Condition></MatchOperator></MatchOperator>`. 같은 XML로 `make new collection at doc with properties {kind:smart album, name:"...", rules:ruleXml}` **성공**, 만들자마자 키워드가 붙은 1장만 보였고, 키워드를 2장 더 붙이니 **3장으로 자동으로 늘었다**(사람이 만든 앨범도 같음). 키워드를 모두 지우니 0장. 일반 앨범(`kind:album`) + `add inside alb variants {...}`, `delete`도 성공 | 키워드 이름만 `Criterion`에 바꿔 넣으면 되므로 **사유별 스마트 앨범을 스크립트로 만들 수 있다.** 키워드 자체는 여전히 사람이 만들어야 한다 |
| 6 일괄 적용 속도 | **일부 확인** | `apply keyword kw to (variants of doc)` 한 번에 20장 적용, 1초 미만(0초 표시), 읽기로 20장 모두 확인. 변형 20장 제거 루프도 1초 미만 | **1000장 시간은 미측정**(카탈로그가 20장뿐). 20장 기준으로는 충분히 빠름 |
| 7 사용자 수정 구분 | **성공 (스냅샷 비교 방식)** | 사전에는 수정 시각·이력 속성이 없다. 대신 반영 시점의 별점·컬러 태그를 저장해 두고, 사람이 화면에서 PHA_8003 별점을 4점으로, PHA_8023 컬러 태그를 빨강으로 바꾼 뒤 스크립트로 읽어 비교하니 **정확히 두 장만 `CHANGED`**, 안 바꾼 PHA_7983은 `same`. 컬러 태그 값은 빨강 = 1 | `apply`가 **반영 직전 값**(별점·컬러 태그·키워드)을 로그 파일에 저장하고, `rollback`은 현재 값이 로그의 "반영 후 값"과 같은 사진만 되돌리고 **다르면(사용자가 바꾼 것) 건드리지 않고 알린다** |

**의미:** 별점과 컬러 태그는 스크립트로 읽고 쓸 수 있다(대안 경로가 열려 있음). 키워드는 **카탈로그마다 사람이 한 번 만들어 두면** 스크립트로 적용할 수 있을 가능성이 높다. 이 경우 PRD의 "도구가 키워드를 붙인다"는 문장에 "처음 한 번 전용 키워드를 만들어 둔다"는 준비 단계가 생긴다.

## 3-1. 결론 (T0.5 완료, 2026-10-19)

**S3(Capture One 연동)은 진행 가능하다.** 키워드 부여(시험 4)가 되기 때문이다. 단 PRD와 설계에 아래 변경이 필요하다.

1. **전용 키워드는 사람이 카탈로그마다 한 번 만들어 둔다.** 스크립트로 새 키워드를 만들 수 없다. `apply`는 시작 시 필요한 키워드가 있는지 확인하고, 없으면 만드는 방법을 안내하며 멈춘다. (키워드 이름: `bcut-eyes_closed`, `bcut-exposure`, `bcut-blur`, `bcut-out_of_focus`, `bcut-review` 등은 T2에서 확정)
2. **스마트 앨범은 스크립트로 만들 수 있다.** 키워드 이름만 바꿔 규칙 XML에 넣으면 되고, 키워드가 붙으면 자동으로 따라온다. T2.6의 "수동 안내"는 필요 없고 스크립트 생성으로 한다 (대안으로 일반 앨범 + `add inside`).
3. **되돌리기:** 반영 전 값을 로그에 저장하고, 사용자가 반영 후 바꾼 값은 건드리지 않는다(시험 7).
4. **반영 전 자동 백업:** `backup now` 명령이 있으므로 `apply` 시작 시 호출할 수 있다.
5. **미측정:** 1000장 일괄 적용 시간(카탈로그가 20장뿐, 20장은 1초 미만), Capture One 버전이 바뀐 뒤의 동작(16.7.1.11에서만 확인).

## 4. 안전 규칙

쓰기 시험은 시험용 카탈로그 `bcut-test`에서만 한다(스크립트가 카탈로그 이름을 확인). 쓰기 전에 원래 값을 파일에 저장하고 복구한다. 실제 작업 카탈로그와 `PILOT*`는 열지 않는다.

## 5. 알아 둘 함정 (스크립트 작성 시)

- `repeat with v in 목록`의 `v`로 `delete (keyword ... of v)`를 하면 **오류 없이 조용히 실패한다**(`try`로 감싸면 보이지 않음). `repeat with i from 1 to (count of 목록)`로 돌며 `set v to item i of 목록`을 써야 한다.
- AppleScript 예약어를 변수 이름으로 쓰면 오류가 난다 (`real`, `named` 등).
- 제거 뒤 읽기에 유령 항목(`missing value`)이 남는다. 반영 확인과 되돌리기 검증은 "이름이 `bcut-`로 시작하는 키워드가 있는가"로 해야 한다.
- **`variants of doc`와 `images of doc`은 문서 전체가 아니라 현재 선택된 컬렉션의 것이다.** 스마트 앨범이 선택돼 있으면 그 앨범의 사진만 나와서 `item 3 of ...`가 오류를 낸다. 전체는 폴더 컬렉션(예: `collection "bcut-test-20" of doc`)의 `variants`로 가져온다.
- `keyword library`는 앱 수준 요소인데 개수가 0이었다. 키워드는 문서(`doc`)에서 찾는다.

## 6. 스마트 앨범 규칙 문법과 미해결 문제 (T2.8, 2026-10-19)

**알아낸 것 (사람이 만든 앨범 `bcut-ui-or`의 `rules`를 읽고, 임시 앨범의 개수로 확인):**

- 문법: 맨 위 `<MatchOperator Kind="AND|OR">` 안에 `<MatchOperator Kind="AND">` 묶음이 여러 개, 묶음 안에 `<Condition Enabled="YES"><Key>…</Key><Operator>n</Operator><Criterion>…</Criterion></Condition>`.
- 별점 키 `IB_I_BASIC_RATING`, 연산자 0 같음 / 1 같지 않음 / 2 이상 / 3 이하 / 4 미만 / 5 초과 (별점 4·2를 준 2장과 18장의 개수로 확인). 연산자 6, 7은 오류.
- 키워드 키 `IB_S_CONTENT_KEYWORDS`, 연산자 0 일치, 1 아님.

**해결 (같은 날):** 한동안 새 규칙의 앨범이 스크립트로는 `bcut 확인` 1장이고 화면에서는 비어 있었는데, **Capture One을 껐다 켜자 모두 기대대로 나왔다.** 원인은 규칙 문법이나 별점 0 직렬화가 아니라 **Capture One의 브라우저·컬렉션 갱신 캐시가 멈춘 것**이었다(아래 6-1). 재시작 뒤 확인한 값:

| 앨범 | 화면 | 스크립트 | 변형 데이터로 계산한 기대 |
|---|---|---|---|
| `bcut-test-20`(폴더) | 20 | 20 | 20 |
| `bcut-ui-or`(키워드 candidate 또는 별점 0) | 19 | 19 | 19 |
| `bcut-ui-keyword-only`(키워드 review) | 4 | 4 | 4 |
| `bcut 확인` | 3 | 3 | 3 |
| `bcut 후보` / `정상` / `제외된 컷` / `눈 감김` | - | 1 / 17 / 3 / 2 | 1 / 17 / 3 / 2 |

**별점이 우선이라는 동작도 실기로 확인:** 후보·확인 컷 PHA_8363에 별점 1을 주니 `확인` 3→2, `제외된 컷` 3→2, `눈 감김` 2→1, `정상` 17→18로 바뀌고(앨범에서 빠져 정상으로 이동), 별점을 0으로 되돌리니 모두 원래대로 돌아왔다. 따라서 **별점 0 직렬화(`IB_I_BASIC_RATING`, 연산자 0, 값 0)는 맞다.**

**함정 추가:**
- `make new collection`에 잘못된 연산자(6, 7)를 주면 오류가 나는데 **깨진 컬렉션이 남고**, 이후 이름 읽기도 오류가 나며 스크립트로 지울 수 없다 (화면에서 삭제).
- 방금 만든 컬렉션을 곧바로 지우면 "이 컬렉션을 삭제할 수 없다"가 날 수 있다. 현재 선택된 컬렉션은 `set current collection of doc to collection "…" of doc`로 바꿀 수 있다.
- 변형의 `name`에는 확장자가 없고(`PHA_8163`), 이미지의 `name`에는 있다(`PHA_8163.CR3`).

### 6-1. 진단 경과와 원인 (2026-10-19)

| 관찰 | 의미 |
|---|---|
| 사람이 화면에서 만든 키워드 단독 앨범 `bcut-ui-keyword-only`(별점 조건 없음)도 스크립트 개수가 어긋남 | 별점 0 직렬화 문제가 아님 |
| 키워드를 붙여도, 별점을 바꿔도, 앨범을 선택해도, `refresh` 명령을 써도 스크립트 개수가 변하지 않음 | 앨범 갱신이 멈춘 상태 |
| 화면의 이미지 브라우저가 `bcut-test-20` 폴더에서도 비어 있음 (폴더 트리는 20장, 검색·필터 없음, 브라우저를 껐다 켜도 같음) | Capture One 화면·컬렉션 캐시 문제 |
| **Capture One만 재시작하자 브라우저와 모든 앨범이 정상으로 돌아옴** (깨진 컬렉션 3개는 지우지 않은 채) | **원인은 갱신 캐시 정지이고, "깨진 컬렉션이 막았다"는 가설은 반증됨.** 정지가 시작된 정확한 계기는 모름(그 사이에 일어난 것: 스크립트로 연속 생성·삭제·롤백, 잘못된 연산자로 만든 깨진 컬렉션, 화면에서 스마트 앨범 편집 시트 취소) |

**운영 지침:**
- 스크립트로 앨범을 만들거나 키워드를 붙인 뒤 **화면이나 앨범 장수가 맞지 않으면 Capture One을 껐다 켠다.** 카탈로그 데이터는 정상이고, 스크립트가 읽는 값(변형의 키워드·별점)은 재시작 전에도 맞았다. 어긋난 것은 앨범 장수와 화면이다.
- 따라서 `apply`의 사후 검증은 앨범이 아니라 **변형의 키워드·별점**으로 한다(지금 방식). 앨범 장수는 검증 기준으로 쓰지 않는다.
- 잘못된 연산자로 만든 앨범은 깨진 컬렉션이 되므로 코드가 확인된 키·연산자·값만 허용한다(`ALLOWED_OPERATORS`).
