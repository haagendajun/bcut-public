# 행사 기록 (Q7 재검토용, devplan T3.4)

**처음 3개 행사**를 쓴 뒤, 이 기록으로 후보(candidate) 경계를 올릴지(오탐 허용 A 엄격 → B 중간) 정한다 (D11). 행사마다 한 줄. 같은 형식의 표 파일은 [event-record-template.csv](event-record-template.csv).

## 행사마다 적을 것

| 항목 | 어떻게 세나 |
|---|---|
| 행사 이름·날짜, 사진 수 | `bcut-log.json`의 `folder`, `photos` |
| 후보·확인·정상 장수 | `bcut-log.json`의 `by_status` |
| **(1) 후보 앨범에서 살린 컷 수** | 후보 앨범에서 별점을 준 컷 수 = 후보 오탐 |
| **(2) 확인 앨범에서 제외한 눈 감김 수** | 확인 앨범 중 실제로 눈이 감겨 제외한 컷 수 |
| **(3) 수동으로 발견한 놓친 눈 감김 수** | `bcut 정상` 앨범을 보다가 눈 감김을 발견한 수 = 미탐 |
| **(4) 후보 앨범 확인에 걸린 시간(분)** *(선택)* | 후보 앨범을 열어서 끝낼 때까지 (스톱워치). 시간 측정을 하지 않기로 해서 안 적어도 된다 |
| 오탐 메모 | 좋은 컷이 걸린 이유(눈을 가늘게 뜬 웃음, 단체 사진 등) |
| 도구·설정 버전 | `bcut --version`, `bcut-log.json`의 `config_version` |

## 판단에 어떻게 쓰나

- 후보 오탐률 = (1) ÷ 후보 장수. A 엄격의 허용선은 정상 컷 약 0.3%(교차 검증 1/350)였다.
- 미탐률 = (3) ÷ (후보+확인에서 확인한 눈 감김 + (3)).
- 3개 행사에서 오탐이 거의 없고 미탐이 많으면 후보 경계를 올려 더 많이 잡는 것을 검토한다. 오탐이 자주 나오면 `calibrate`로 재보정하거나 경계를 내린다.
- 한 행사 표본은 작다. 3개를 합쳐서 본다.
