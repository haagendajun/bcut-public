# 흔들림·초점 판정 실험 (T1.6, T1.7, T1.15, T1.16)

작성: 2026-10-19. 구현: `bcut.score.sharpness`, `bcut.detect.sharpness`, `bcut.detect.face_sharp`, `bcut.synth`. 평가: `python eval/evaluate_sharpness.py`.

## 1. 결론 (먼저)

- **v1 기본값으로 `review`(사람이 확인) 전용으로 넣는다.** 실제 결함이 거의 없어(아래 3장) 정탐을 잴 수 없기 때문이다.
- **오탐: 실제 사진 535장에서 0장** (정상·표정 주의 포함, 100% 확대로 결함 없음 확인한 컷).
- **전체 흔들림·흐림은 잘 잡는다.** 합성 가우시안 흐림 sigma 3 이상은 100%, sigma 2는 59%.
- **얼굴만 흐린 컷(초점 실패)과 가벼운 방향성 흔들림은 약하다.** 얼굴이 작은 컷은 아예 판정하지 않는다.
- **처음으로 실제 흔들림 컷 2장이 걸렸다.** EVENT_A의 PHA_8150, 8151(셔터가 잘못 눌린 컷, 사진을 열어 확인함). 둘 다 "애매"로 표시돼 평가에서는 빠져 있던 컷이다. 실제 결함 20장 기준에는 한참 모자란다.

## 2. 판정 규칙

흐림 지표는 "재블러" 방식이다(`detect/sharpness.py`). 한 번 더 흐리게 했을 때 이웃 픽셀 밝기 변화가 얼마나 줄어드는지를 본다. 0~1이고 **클수록 흐리다**. 가로·세로 방향 중 더 흐린 쪽을 쓴다 (대각선까지 넣으면 정상 사진 값이 올라가 정상과 흐린 사진이 겹쳐서 뺐다).

| 사유 | 조건 | 의미 |
|---|---|---|
| `blur` (흔들림·전체 흐림) | 가장 선명한 타일 쪽(타일 흐림 하위 10%)이 **≥ 0.55** | 사진 어디에도 선명한 곳이 없다. 보케 배경 인물은 얼굴 쪽 타일이 선명해 안 걸린다 |
| `out_of_focus` (초점 실패) | 얼굴 흐림 **≥ 0.62**이고 `blur` 조건은 아님. 얼굴 폭(풀 해상도) **≥ 420px**인 얼굴만 | 얼굴은 흐린데 어딘가는 선명하다 |

- 얼굴 흐림은 풀 해상도(8192px)에서 얼굴 안쪽만 재서 구한다. 분석 입력(2048px)에서는 가벼운 흔들림이 몇 픽셀 번짐이라 거의 안 보이기 때문이다. 얼굴이 있을 때만 풀 해상도로 읽고, 큰 얼굴 3개까지만 잰다.
- 얼굴은 눈 감김·노출과 같은 기준으로 고른다(가장 큰 얼굴 면적의 0.5배 이상).
- 얼굴이 없으면 `blur` 규칙(사진 전체)만 쓴다 (T1.7).
- 등급은 `review` 전용. 설정에서 `candidate`로 올릴 수 있다 (`scan`의 `sharpness_tier`).
- 속도: 얼굴 풀 해상도 측정을 넣고도 **약 45 ms/장**(6프로세스, 눈 감김·노출 포함).

## 3. 실제 사진의 분포와 경계 선택

실제 사진 535장(EVENT_A 397 + EVENT_B 138, "애매" 제외)은 사용자가 100% 확대로 흔들림·초점 결함이 없다고 본 컷이다. **잡으면 오탐이다.**

- 얼굴 흐림은 **얼굴이 작을수록 정상 사진에서도 높게 나온다.** 얼굴 안쪽 폭과 흐림의 상관은 -0.56(EVENT_A)/-0.48(EVENT_B)이고 질감과는 거의 무관했다. 같은 초점이어도 작은 얼굴은 풀 해상도에서 픽셀 수가 적어 덜 선명하게 측정된다.
- 폭 구간별 실제 사진의 최대값(얼굴 흐림):

| 얼굴 폭(px) | 장수 | 실제 최대 | 실제 중앙 |
|---|---|---|---|
| < 300 | 10 | 0.698 | 0.616 |
| 300~360 | 11 | 0.730 | 0.563 |
| 360~420 | 229 | 0.739 | 0.553 |
| 420~480 | 140 | 0.569 | 0.508 |
| 480~600 | 18 | 0.549 | 0.382 |
| 600~800 | 65 | 0.469 | 0.372 |
| ≥ 800 | 38 | 0.442 | 0.308 |

  420px 미만에서는 실제 최대값(0.70~0.74)과 합성 흐림(gauss4 중앙 0.71~0.85)의 간격이 좁아, 오탐 0을 지키면 재현율이 구간에 따라 20~75%로 갈린다. 그래서 **420px 미만 얼굴은 얼굴 규칙을 쓰지 않기로** 했다(단순함과 안전 우선). 420px 이상에서는 실제 최대 0.569에서 여유 0.05를 두어 **0.62**.
- 전체 흐림 규칙의 0.55는 가장 선명한 타일 쪽의 실제 최대값에서 여유를 둔 값이다 (오탐 0).
- 이 경계는 **두 행사의 극값 근처**에서 정했다. 낙관적일 수 있다. 홀드아웃(EVENT_A 나머지 560장)과 새 행사로 다시 확인해야 한다.

## 4. 평가 결과 (운영 코드로, `eval/evaluate_sharpness.py`)

오탐: **EVENT_A 0/397, EVENT_B 0/138.**

합성 재현율 (경향만. 실제 결함이 아니다):

| 전체 흐림 (분석 입력 기준 픽셀) | 재현율 |
|---|---|
| 가우시안 sigma 1 | 0% (일부러 안 잡음) |
| sigma 2 | 59% |
| sigma 3 | 100% |
| sigma 5 | 100% |
| 모션 8px / 16px / 32px | 3% / 17% / 27% |

| 얼굴만 흐림 (풀 해상도 기준 픽셀, 얼굴 규칙이 적용되는 얼굴 대비) | 재현율 |
|---|---|
| 가우시안 sigma 2 / 4 / 8 | 83% / 100% / 100% |
| 모션 8px / 16px / 32px | 52% / 76% / 79% |

얼굴 규칙은 얼굴이 있는 사진의 **절반 남짓**에만 적용된다(나머지는 얼굴이 420px보다 작음).

## 5. 한계

| # | 내용 | 대응 |
|---|---|---|
| 1 | **실제 결함이 2장뿐이다.** 정탐률은 잴 수 없고 재현율은 거의 전부 합성이다 | `review` 전용. 실제 결함 20장 이상이 쌓이면 평가·승급 검토 (devplan 1-F). 새 행사에서 걸린 컷을 사람이 확인해 정오를 기록 |
| 2 | **방향성 가벼운 흔들림(모션 8~16px)은 전체 흐림 규칙으로는 거의 못 잡는다** (3~17%). 분석 입력이 2048px이라 번짐이 작아 보인다 | 얼굴이 있고 420px 이상이면 얼굴 규칙이 일부 보완(52~76%). 나머지는 사람이 본다 |
| 3 | **작은 얼굴(폭 < 420px)은 초점 판정을 안 한다.** 이런 컷이 사진의 절반쯤이다 | 정상 사진의 값과 겹쳐 오탐 없이 구분할 수 없었다. 전체 흐림(`blur`)은 계속 적용된다 |
| 4 | **한 행사 극값으로 경계를 정했다.** 다른 카메라·렌즈·촬영 스타일에서는 어긋날 수 있다 (노출에서 이미 큰 행사 간 차이를 봤다) | 홀드아웃과 새 행사에서 확인, 설정으로 조정 |
| 5 | 의도한 보케·장노출 효과, 손·소품이 얼굴을 가리는 컷은 걸릴 수 있다 | `review`라 비용은 사람이 한 번 더 보는 것 |
| 6 | 입력은 카메라가 만든 JPEG다. 샤프니스 설정, 노이즈 제거에 따라 값이 달라진다 | 판정은 "촬영된 그대로"를 본다 |
