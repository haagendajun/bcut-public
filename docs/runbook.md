# 런북: 행사 사진 B컷 후보 걸러내기

**초안 (2026-10-19).** 명령은 실제로 돌려 확인했다(개발자가 행사 A 400장으로 ②, ④, ⑤, `rollback`을 실행, [rehearsal-report.md](rehearsal-report.md)). **처음 쓰는 사람이 이 문서만 보고 끝까지 해 본 적은 없고, ③과 ⑥(화면에서 하는 단계)은 리허설에서 실행하지 못했다.** 막히는 곳이 있으면 이 문서를 고친다.

**실행 전에:** 영상 통화·화면 녹화·영상 인코딩 같은 무거운 작업을 끈다. 맥이 바쁘면 `apply`·`rollback`이 2~3배 느려진다(리허설에서 `apply --commit`이 28초 → 86초).

도구가 하는 일은 **후보를 표시하는 것까지**다. 사진을 지우지 않고, 어떤 컷을 뺄지는 사람이 정한다. 모든 명령은 먼저 미리보기(dry-run)로 보여 주고, `--commit`을 붙여야 실제로 바꾼다.

## 0. 한눈에 보기

```
① 사진을 Capture One 카탈로그에 가져온다 (평소대로)
② bcut scan      → 후보·확인 리포트(CSV, HTML)
③ 리포트를 눈으로 훑는다 (HTML)
④ bcut apply     → 후보·확인 컷에 전용 키워드 (미리보기 → --commit)
⑤ bcut albums    → 전용 스마트 앨범 (카탈로그마다 한 번)
⑥ Capture One에서 후보 앨범 확인 → 오탐은 별점으로 살리기 → 나머지는 제외 → 정상 앨범에서 다음 작업
(재요청) bcut 제외된 컷 앨범에서 대안을 찾는다
(문제 시) bcut rollback → 전용 키워드만 떼어 원래대로
```

## 1. 처음 한 번만

| 할 일 | 방법 |
|---|---|
| 설치 | [install.md](install.md) |
| **점검** | `bcut doctor --catalog "<카탈로그 이름>"` — Python·라이브러리·Capture One 버전, 연결·자동화 권한, 전용 키워드 유무를 한 번에 확인한다(읽기만 한다). 행사 처리 전에 한 번 돌려 두면 막히는 곳을 미리 알 수 있다 |
| Capture One 자동화 권한 | 처음 `apply`를 돌릴 때 뜨는 팝업에서 허용. 놓쳤으면 시스템 설정 > 개인정보 보호 및 보안 > 자동화 |
| **카탈로그마다 전용 키워드 만들기** | [capture-one-setup.md](capture-one-setup.md). 키워드는 스크립트로 만들 수 없다. 6개(`bcut-candidate`, `bcut-review`, `bcut-eyes_closed`, `bcut-exposure`, `bcut-blur`, `bcut-out_of_focus`)를 미리 모두 만들어 두면 안전하다 |

아래 명령의 `bcut`은 `~/.venvs/photo-select/bin/bcut`이다.

## 2. 행사 하나를 처리하는 순서

변수를 정해 두면 편하다 (행사 폴더, 카탈로그 이름, 결과 폴더).

```bash
EV="$HOME/photo-select-data/events/<행사 폴더>"
CAT="<Capture One 카탈로그 이름>"
OUT="$HOME/photo-select-data/reports/<행사 이름>"
```

### ① 가져오기
평소처럼 사진을 Capture One 카탈로그에 가져온다. **카탈로그가 열려 있어야** `apply`가 돈다.

### ② 분석 (`scan`)

```bash
bcut scan --folder "$EV" --out "$OUT"
```

- 사진은 읽기만 한다. 결과 폴더는 행사 폴더 **밖**이어야 한다(안이면 거부).
- 1500장 기준 약 1분(내장 SSD, 6개 병렬, 맥이 한가할 때). 외장 드라이브는 더 걸릴 수 있다. (리허설 400장: 23초)
- 끝나면 요약이 나온다: B컷 후보 / 사람이 확인 / 정상 / 얼굴 없음 / 판정 불가, 사유별 장수.
- 결과 폴더에 `bcut-report.csv`, `bcut-report.html`, `bcut-log.json`이 생긴다.

### ③ 리포트 확인

`bcut-report.html`을 브라우저로 연다. 후보·확인 컷을 썸네일로 훑고, 좋은 컷이 보이면 "살리기"로 표시해 둔다(브라우저에만 기억한다). **이 파일에는 사진 썸네일이 들어 있으니 이 컴퓨터에서만 쓰고 다른 사람에게 보내지 않는다.**
후보 비율이 이상하게 높으면(후보 20% 초과, 후보+확인 40% 초과) `apply`가 멈춘다. 그 전에 폴더나 설정이 맞는지 본다.

### ④ 키워드 붙이기 (`apply`)

```bash
bcut apply --folder "$EV" --catalog "$CAT" --out "$OUT"            # 미리보기
bcut apply --folder "$EV" --catalog "$CAT" --out "$OUT" --commit \
    --catalog-backup-dir "$HOME/photo-select-data/backups/$CAT"      # 실제 반영
```

- **미리보기**에서 후보·확인 장수, 사유별 장수, 카탈로그에서 찾은/못 찾은 컷, 붙을 키워드를 확인한다.
- 미리보기가 "카탈로그에 전용 키워드가 없다"고 멈추면 [키워드를 만든 뒤](capture-one-setup.md) 다시 한다. 아무것도 바뀌지 않았다.
- `--commit`은 반영 전에 카탈로그를 백업하고(`--catalog-backup-dir`), 컷마다 직전 값을 `bcut-backup.json`에 저장한 뒤 키워드를 붙이고, **별점·컬러 태그가 그대로인지 스스로 검증한다.** 같은 명령을 다시 실행해도 같은 결과다(이미 붙은 키워드는 건너뜀).
- 중간에 멈추면 "일부만 반영됐을 수 있다"고 알리니, **같은 명령을 다시 실행하면 이어서 한다.**
- 400장 기준 28초(조용할 때)~86초(맥이 바쁠 때). 1500장 환산은 약 2분~5분(추정).

### ⑤ 스마트 앨범 (`albums`, 카탈로그마다 처음 한 번)

```bash
bcut albums --catalog "$CAT"            # 미리보기
bcut albums --catalog "$CAT" --commit
```

만들어지는 앨범: `bcut 후보`, `bcut 확인`, `bcut 정상`, `bcut 제외된 컷`, `bcut 눈 감김`, `bcut 노출`, `bcut 흔들림`, `bcut 초점 실패`. 이미 있으면 건드리지 않는다. 앨범은 키워드와 **별점**을 따라 자동으로 바뀐다.

### ⑥ Capture One에서 확인하고 제외

**먼저 알아 둘 것 (화면 기준, 리허설에서 실행해 보지 못함):**
- **앨범 위치:** Capture One 왼쪽 **라이브러리** 패널의 컬렉션 목록에서 이름이 `bcut `으로 시작하는 앨범(`bcut 후보` 등)을 클릭하면 그 앨범의 사진이 가운데 브라우저에 나온다. 앨범이 안 보이면 ⑤를 했는지, 카탈로그 이름이 맞는지 본다.
- **별점 주기:** 사진을 클릭해 선택하고 키보드 숫자 **1~5**를 누르거나 썸네일의 별 아이콘을 누른다(Capture One 기본 설정 기준, 이 키 동작은 아직 확인하지 못했다). 별점을 지우려면 숫자 **0**. **별점이 하나라도 있으면 "살린 컷"으로 본다.**
- **무엇을 보고 판단하나:** 후보는 눈 감김이 대부분이다. 썸네일을 키워서(확대) 눈이 정말 감겼는지 본다. 가늘게 뜬 웃음처럼 눈이 떠 있으면 오탐이다.

1. **`bcut 후보`** 앨범을 연다. 눈 감김 등 분명한 B컷 후보다. 좋은 컷이 섞여 있으면 **별점을 하나라도 준다** → 그 컷은 후보에서 빠지고 `bcut 정상`으로 간다 (키워드를 지울 필요 없음).
2. **`bcut 확인`** 앨범은 도구가 확신하지 못한 컷(경계 구간, 단체 사진, 좁은 눈, 노출·흔들림·초점)이다. 한 장씩 사람이 판단한다. 살릴 컷은 같은 방식으로 별점을 준다.
3. 남은 후보·확인 컷은 **제외 상태**다(삭제된 것이 아니다). `bcut 정상` 앨범에서 다음 작업(유사컷 비교 등)을 시작한다.
4. 앨범이 비어 있거나 장수가 안 맞아 보이면 **Capture One을 껐다 켠다**(카탈로그의 데이터는 정상이다).

## 3. 재요청이 왔을 때

`bcut 제외된 컷` 앨범을 연다. 도구가 걸렀고 아직 별점을 안 준 컷이 **삭제 없이 모두 남아 있다.** 사유별로는 `bcut 눈 감김` 등 앨범에서 본다. 대안으로 쓸 컷에 별점을 주면 제외에서 빠진다.
수동으로 제외한 컷(도구가 걸러낸 것이 아님)은 이 앨범에 없다. 전체 폴더에서 별점이 낮은 컷으로 찾는다.

## 4. 오탐(좋은 컷이 후보에 있음) 대응

1. 그 컷에 별점을 준다(위 ⑥-1).
2. **기록한다** (5장). 어떤 컷이 왜 걸렸는지(눈을 가늘게 뜬 웃음 등).
3. 같은 유형이 반복되면 라벨을 모아 `calibrate`로 경계를 다시 정한다:

```bash
bcut calibrate --folder "$EV" --labels <라벨.csv> --out <새설정.toml>
bcut scan --folder "$EV" --out "$OUT" --config <새설정.toml>
```

라벨은 `file,label` 열(`B`, `OK`, `OK_EXPR`)이다. 라벨이 B 10장, 정상 30장 미만이면 `calibrate`가 거부한다. 같은 라벨로 잰 재현율은 낙관적이니 새 행사로 확인한다.

## 5. 행사마다 기록할 것 (Q7 재검토용)

[event-record.md](event-record.md)의 표에 행사마다 한 줄씩 적는다 — 후보 앨범에서 **살린 컷 수**, 확인 앨범에서 **제외한 눈 감김 수**, **수동으로 발견한 놓친 눈 감김 수**, **후보 앨범 확인에 걸린 시간**. 처음 3개 행사 뒤 이 기록으로 후보 경계를 올릴지 정한다.

## 6. 되돌리기 (`rollback`)

```bash
bcut rollback --folder "$EV" --catalog "$CAT" --out "$OUT"           # 미리보기
bcut rollback --folder "$EV" --catalog "$CAT" --out "$OUT" --commit
```

- `apply`가 붙인 전용 키워드만 뗀다. **별점·컬러 태그와 사용자가 붙인 키워드는 건드리지 않는다.**
- 반영 후 사용자가 별점·태그를 바꾼 컷은 "건드리지 않음"으로 목록에 알려 준다.
- 이미 뗀 컷은 그대로 둔다(다시 실행해도 같다). `bcut-backup.json`은 지우지 않는다.
- 카탈로그 전체를 되돌리고 싶으면 `--catalog-backup-dir`로 만든 카탈로그 백업을 쓴다 (Capture One에서 백업을 연다).

## 7. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| `카탈로그에 전용 키워드가 없다: …` | 키워드를 만든다([capture-one-setup.md](capture-one-setup.md)). 아무것도 바뀌지 않았다 |
| `열려 있는 카탈로그가 지정한 것과 다르다` | Capture One에서 `--catalog` 이름의 카탈로그를 연다. 아무것도 바뀌지 않았다 |
| `이 터미널이 Capture One을 제어할 권한이 없다` | 시스템 설정 > 개인정보 보호 및 보안 > 자동화에서 터미널의 Capture One을 켠다 |
| `Capture One이 실행 중이 아니다` / `열려 있는 카탈로그가 없다` | Capture One을 실행하고 카탈로그를 연다 |
| `Capture One이 제때 응답하지 않았다` | Capture One이 멈췄는지 본다. 껐다 켠 뒤 같은 명령을 다시 한다(이미 한 일은 건너뜀) |
| `비정상 비율 경고로 … 아무것도 바꾸지 않았다` | 후보가 너무 많다. 폴더·설정을 확인하고, 맞다면 `--ignore-ratio-warning` |
| `카탈로그에서 못 찾은 컷`이 있다 | 카탈로그에 그 사진이 없거나 폴더가 다르다. 맞는 카탈로그인지 본다. 찾은 컷만 하려면 `--allow-partial` |
| 앨범이 비어 있거나 장수가 이상, 브라우저가 비어 있음 | Capture One을 껐다 켠다 |
| `결과 폴더가 행사 폴더 안이다` | `--out`을 행사 폴더 밖으로 지정한다 |
| 반영 후 `검증 실패` | 별점·태그가 바뀌었거나 키워드가 빠졌다는 뜻이다. 출력의 파일을 확인하고 `rollback`한다 |

**무엇부터 볼까:**

1. `bcut doctor --catalog "$CAT"` — 환경이나 연결 문제(권한, 카탈로그 불일치, 키워드 없음, 버전)를 먼저 가려 준다.
2. 결과 폴더의 `bcut-actions.jsonl` — `apply`·`rollback`을 돌릴 때마다 한 줄씩 남는다(미리보기도). 언제, 어느 카탈로그에, 어떤 모드로 돌렸고, 반영 장수·키워드별 개수·경고·검증 실패·중단 사유·소요 초가 있다. 파일 이름은 담지 않는다. "어제 apply가 끝까지 됐나"를 여기서 본다.
3. `bcut-log.json`(`scan` 기록: 시작·종료, 장수, 장당 초, 등급·사유별 개수, 처리 못 한 파일, 설정·버전), `bcut-report.csv`(컷별 등급·사유·확신도·수치, 열 이름은 [file-contracts.md](file-contracts.md)), `bcut-backup.json`(반영 전후 값).
4. 도구 버전은 `bcut --version`이고 CSV·로그·실행 기록에 모두 적혀 있다. 문의할 때 `bcut doctor` 출력과 `bcut-actions.jsonl`의 마지막 줄을 같이 알려 주면 된다.

## 8. 하지 말 것

- 실제 작업 카탈로그에서 처음 시험하지 않는다. 복제본에서 먼저 한다.
- `bcut-report.html`을 다른 사람에게 보내지 않는다(썸네일이 들어 있다).
- 키워드 이름을 바꾸거나 지우지 않는다(앨범과 `rollback`이 이름으로 찾는다).
- Capture One 버전을 올리기 전에 먼저 `docs/applescript-findings.md`의 시험 7개를 다시 돌린다(16.7.1에서만 확인했다).
