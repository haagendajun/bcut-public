# 기획안: 셀렉 훑기 모드

작성일: 2026-10-20 · 상태: **기획안 (구현 전)** · 근거: 사용자 인터뷰 4라운드(Q1~Q23), `GLOSSARY.md`, `docs/adr/0007~0008`
관련 문서: [PRD.md](../PRD.md) FR-21~27 · [IA.md](../IA.md) 13장 · [uj.md](../uj.md) CUJ-04 · [erd.md](../erd.md)

> 표기: 인터뷰에서 사용자가 답한 것은 **[확정]**, 제가 정한 값은 **[제안]**, 근거 없는 전제는 **[가정]** 이다. 코드는 건드리지 않았고 DB도 바꾸지 않았다.

## 1. 한 문장

큰 사진을 한 장씩 키보드로 넘기며 **셀렉 / 보류 / 버릴 컷**을 표시하고, 도구의 판정은 고르기를 돕는 보조 정보로 보여 주는 화면(훑기 모드)을 추가한다.

## 2. 왜 필요한가

| 인터뷰에서 나온 것 | 의미 |
|---|---|
| 현업의 중심은 안 좋은 사진을 거르는 것이 아니라 **좋은 사진을 고르는 것** [확정] | 지금 앱은 버릴 컷 찾기에 맞춰져 있어 고르는 화면·표시·내보내기가 없다 |
| 불편한 곳: 의심 컷을 훑는 시간, 도구가 놓친 컷을 직접 찾는 일, 나누어 담은 뒤 확인, 어디부터 볼지 헷갈리는 화면 [확정] | 한 화면에서 훑고 표시하는 흐름이 필요하다 |
| 놓친 컷은 앱 밖에서 고르거나, 앱에서 눈으로 찾지만 표시할 방법이 없음 [확정] | 앱 안에서 표시하고 폴더로 담을 수 있어야 한다 |
| 목표: 고르는 시간을 줄이고, 좋은 컷을 실수로 버릴 위험을 줄인다 [확정] | 지표는 장당 훑는 시간과 표시 취소 가능성 |
| 규모: 한 행사 1500장 안팎, 맥북 [확정] / 셀렉은 공항패션 30장 이내, 행사사진 100~300장 [확정] | 키보드로 한 장씩 넘기는 방식, 목표 장수는 앱이 정하지 않는다 |
| 지금은 Capture One에서 별점·컬러 태그로 고른다 [확정] | 셀렉 결과를 Capture One으로 보낼지는 열린 질문 (8장) |

## 3. 무엇을 만드는가 (범위)

| # | 기능 | 한 줄 설명 | 우선순위 [제안] |
|---|---|---|---|
| 1 | **훑기 모드** (FR-21) | 큰 사진 + 오른쪽 패널 + 아래 필름스트립. 촬영 순서대로 보여 준다 | Must |
| 2 | **표시** (FR-22) | 셀렉(S) / 보류(M) / 버릴 컷(X). 표시하면 자동으로 다음 사진, 같은 키를 다시 누르면 해제 | Must |
| 3 | **안전장치** (FR-23) | ⌘Z 실행 취소, 표시 취소 가능(이력은 남음), 나누어 담기 전 최종 확인 화면 | Must |
| 4 | **판단 돕는 정보** (FR-24) | 얼굴 박스, 눈 부분 확대, 의심한 이유 문장, 이웃 컷 필름스트립 | Should |
| 5 | **셀렉 폴더로 담기** (FR-25) | 나누어 담기에 셀렉·보류 폴더 추가 | Must |
| 6 | **훑기 기록** (FR-26) | 훑은 시간·본 사진 수·표시 수 자동 기록 | Should |
| 7 | **기존 "남기기" 이전** (FR-27) | 브라우저에 남은 "남기기"를 셀렉으로 옮기고 남기기는 없앤다 | Must |

### 범위 밖 (이번에는 하지 않음) [확정]

- 연사·비슷한 사진 묶기(가장 나은 한 장 고르기)
- 나누어 담은 뒤 되돌리기 전용 화면
- 지난 검사 이력 목록
- 슈파베이스 실제 연동 코드 (표시는 로컬에 먼저 저장하고, 연동 후 같은 경로로 올린다) **[가정]**
- **Capture One에도 표시하기**는 이번 단계(S5)가 아니라 **S6 별도 단계**다 [확정, 12장 참고]

## 4. 사용 흐름

1. 요약 화면에서 **"훑기 시작"**(마지막 위치가 있으면 "이어서 훑기")을 누른다
2. 훑기 모드가 열린다: 촬영 순서대로 큰 사진 한 장
3. 사용자가 **S / M / X**로 표시하면 다음 사진으로 넘어간다 (←/→로 직접 이동)
4. 도구가 의심한 컷은 필름스트립에서 **흐리게** 보이고, **D 키**로 "의심 컷 건너뛰기"를 켜고 끌 수 있다 [확정, Q18]
5. 잘못 눌렀으면 **⌘Z**
6. 끝까지 보거나 Esc로 나가면 **최종 확인 화면**: 셀렉 N장 / 보류 M장 / 버릴 컷 K장 / 표시 안 한 U장
7. "나누어 담기"로 폴더를 만든다 (또는 "계속 훑기"로 돌아간다)
8. 마지막에 **R 키**로 보류만 모아 다시 볼 수 있다 [제안]

촬영 순서는 파일 이름순으로 대신한다 **[가정]** (카메라 연번이 촬영 순서와 같다고 본다. 어긋나면 촬영 시각 기준으로 바꾼다).

## 5. 표시 규칙 [확정, Q13·Q19·Q20]

- 표시는 세 가지: **셀렉 / 보류 / 버릴 컷**. 사진 한 장에는 동시에 하나만 있다
- 이미 표시가 있는 사진에 다른 표시를 달면 앞의 표시는 자동으로 취소된다 (삭제하지 않고 취소 시각만 기록)
- 도구가 뭐라고 판정했든 사용자의 표시가 우선이다. "남기기"는 없어지고 셀렉이 그 역할을 한다
- 표시를 달지 않은 사진은 도구 판정대로 기존 폴더로 간다

## 6. 나누어 담기 폴더 [확정, Q21·Q7]

| 폴더 | 들어가는 사진 |
|---|---|
| **셀렉** (맨 앞) | 셀렉한 사진. 셀렉 폴더에만 담긴다 |
| **보류** | 보류한 사진 |
| 버릴 것 같은 컷 | 도구가 찾은 버릴 것 같은 컷 + 사용자가 정한 버릴 컷 (둘 다 같은 폴더, DB 기록에서 구분) |
| 직접 확인 / 이상 없음 / 판단 못 함 / 문제 종류별 | 표시를 달지 않은 사진이 지금처럼 판정별로 |

원본은 읽기만 하고, 사본을 만들며, 파일을 삭제하지 않는 규칙은 그대로다.

## 7. 디자인 방향 [확정, Q10]

**훑기 화면만 "라이트 테이블"**(어두운 배경, 사진이 주인공). 시작·요약·나누어 담기는 지금의 밝은 스타일을 유지한다.

| 불편 [확정, Q4] | 대응 |
|---|---|
| 글자·태그·버튼이 많아 정신없음 | 한 화면에 정보는 3가지만: 의심 이유 한 줄, 눈 확대, 지금 표시. 나머지는 단축키 안내 한 줄 |
| 사진이 작거나 잘림 | 사진이 화면의 대부분을 차지하고 잘리지 않는다 (맞춤 표시, Z로 100% 확대) |
| 크게 볼 때 정보 부족 | 얼굴 박스(F로 켜고 끔), 눈 확대, 의심한 이유와 정도, 이웃 컷 필름스트립 |

- 표시는 **색 + 아이콘 + 글자**로 보여 준다 (셀렉 파랑·체크, 보류 노랑·점, 버릴 컷 회색·취소선). 색만으로 구분하지 않는다
- 필름스트립에서 의심 컷은 흐리게, 지금 사진은 테두리, 표시한 사진은 색 표시
- 상단에 진행 표시: **셀렉 N장 · 본 사진 M / 전체 T** (목표 장수는 정하지 않는다)

### 단축키 [제안]

| 키 | 동작 |
|---|---|
| ← / → | 이전·다음 사진 |
| S / M / X | 셀렉 / 보류 / 버릴 컷 (같은 키 다시 누르면 해제) |
| ⌘Z | 실행 취소 |
| D | 의심 컷 건너뛰기 켜기·끄기 |
| F | 얼굴 박스 켜기·끄기 |
| Z | 100% 확대 |
| R | 보류만 보기 |
| Esc | 훑기 마치고 최종 확인으로 |

## 8. 데이터 변경 (ERD 반영, 아직 DB에는 적용하지 않음)

[erd.md](../erd.md)에 반영했다. 현재 DB는 비어 있어 바꾸기 쉽다.

| 변경 | 내용 |
|---|---|
| `keep_marks` → **`photo_marks`** | `kind`(pick/maybe/discard) 열 추가. 취소되지 않은 표시는 사진당 하나 (ADR-0008) |
| **`review_sessions`** 신규 | 훑기 한 번의 시작·끝·본 사진 수·셀렉/보류/버릴 컷 수. 끝날 때 한 번에 올린다(삭제·수정 없음) |
| `sort_items.kept` → **`mark_kind`** | 나누어 담을 때 적용된 표시(없으면 null) |
| `sorts.counts` | 폴더별 장수에 셀렉·보류 포함 |

권한(RLS)과 열 단위 수정 권한도 같이 바뀐다: `photo_marks`는 `cancelled_at`만 수정 가능, `review_sessions`는 추가만 가능.

## 9. 성공 지표 [제안]

| 지표 | 측정 | 비고 |
|---|---|---|
| **장당 훑는 시간** | 훑기 기록 (끝 시각 − 시작 시각) ÷ 본 사진 수 | 사람이 손으로 하던 기준값은 없다(측정하지 않기로 함). 행사 간 추이로 본다 |
| **셀렉 중 도구가 의심했던 비율** | 셀렉 사진 중 도구 등급이 "버릴 것 같은 컷"인 것 | 도구 오탐 지표 (Q7 허용선 약 0.3%와 비교) |
| **도구가 놓친 컷 수** | 사용자가 버릴 컷으로 표시했지만 도구 등급이 "이상 없음"이던 사진 | 미탐 지표, 임계값 보정 자료 |
| 표시 취소 비율 | 취소된 표시 ÷ 전체 표시 | 실수·망설임 정도 |

## 11. 만드는 순서 [제안]

| 단계 | 내용 |
|---|---|
| 1 | 표시 저장(로컬) + 훑기 모드 기본(사진·키보드·표시·필름스트립) |
| 2 | 최종 확인 + 셀렉·보류 폴더 담기 + 남기기 이전 |
| 3 | 얼굴 박스·눈 확대·이유 문장 |
| 4 | 훑기 기록 + DB 변경 적용(`photo_marks`, `review_sessions`) |

단계별 기간은 근거가 없어 정하지 않았다.

## 12. S6: Capture One에도 표시하기 [확정, 2026-10-20]

S5(훑기 모드)가 안정된 뒤 별도 단계로 한다. 추천안 **A(전용 키워드만)**를 택했고, 별점·컬러 태그를 직접 주는 방법(B)은 하지 않는다.

| 항목 | 내용 |
|---|---|
| 켜는 곳 | 나누어 담기 화면의 옵션 "Capture One에도 표시하기" (SO-02-APP) |
| 하는 일 | 셀렉·보류·버릴 컷 사진에 전용 키워드 `bcut-셀렉` / `bcut-보류` / `bcut-버릴컷` 부여 (기존 `apply` 재사용) |
| 건드리지 않는 것 | 기존 별점·컬러 태그 |
| 안전장치 | 붙이기 전 백업, `rollback`으로 되돌리기, 카탈로그 이름 확인 |
| 사전 준비 | 키워드는 카탈로그마다 사람이 한 번 만들어 둔다(없으면 방법 안내 후 중단). Capture One이 켜져 있고 해당 카탈로그가 열려 있어야 한다. 처음에 맥의 자동화 허용 창이 뜰 수 있다 |
| 파일 이름이 겹칠 때 | 그 사진은 건너뛰고 알린다 |
| 결과 | Capture One의 키워드 조건 스마트 앨범("bcut 셀렉")에서 별점·컬러를 이어서 준다 |
| 미확인 | 셀렉·보류·버릴 컷에 대한 키워드 부여는 아직 시험하지 않았다(기존 검증은 의심 컷 대상, 16.7.1.11). 속도는 400장 28초 기준으로 셀렉 30~300장이면 수 초~수십 초로 **추정** |
