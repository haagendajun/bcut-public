# 홀드아웃(H) 라벨링과 평가 절차

**목적:** 도구의 임계값을 정하는 데 한 번도 쓰지 않은 새 사진 560장으로, 정탐률과 오탐을 **정직하게** 잰다. 지금까지의 수치(정탐 94%, 후보 오탐 약 0.3%)는 임계값을 정한 사진에서 나온 값이라 낙관적이다. 이 평가가 그 값을 확인해 준다.

**대상:** EVENT_A 행사 원본 폴더의 나머지 560장 (`PHA_7780`~`PHA_7982` 203장, `PHA_8383`~`PHA_8739` 357장). 이미 쓴 400장(`PHA_7983`~`PHA_8382`)과 겹치지 않는다. 확인(2026-10-20): iCloud의 원본 폴더에 CR3 960장이 있고 이 560장은 모두 내려받아져 있다(13.2GB).

## 0. 가장 중요한 규칙 (평가가 무효가 되지 않으려면)

1. **라벨링이 끝날 때까지 도구 결과를 보지 않는다.** 이 560장에 `bcut scan`을 돌리지 않고, 리포트(HTML·CSV)도 열지 않는다. 도구의 후보를 본 뒤에 라벨을 붙이면 라벨이 도구에 끌려가서 정탐률이 부풀려진다.
2. **임계값을 먼저 동결한다.** 아래 1장의 동결 기록을 남긴 뒤에는 임계값·규칙·코드의 판정 로직을 바꾸지 않는다. 바꾸고 싶어지면 **이 560장은 더 이상 홀드아웃이 아니다**(새 행사가 필요하다).
3. **평가는 한 번만 한다.** 결과가 마음에 안 들어 보여도 다시 튜닝하고 같은 560장으로 재평가하지 않는다.
4. **합격 기준을 결과를 보기 전에 정해 둔다** (아래 5장).
5. 이 560장을 지금까지 **열어 보거나 라벨링한 적이 없어야** 한다. 이 프로젝트의 평가·튜닝 코드는 이 사진을 읽은 적이 없다. **사용자 확인 (2026-10-20): 이 560장은 이전에 훑어본 적이 없다.**

## 1. 시작 전: 동결 기록 — **완료 (2026-10-20 08:07)**

`eval/holdout-freeze.json`에 아래를 남긴다 (시각 포함, 이후 수정하지 않는다).
- 도구 버전, 설정 버전, 임계값 전체 값(눈 감김 0.134·0.162, 노출, 흔들림·초점 규칙), `requirements-lock.txt`의 해시, 테스트 통과 수
- 홀드아웃 파일 560개의 이름 목록 해시 (나중에 같은 560장인지 확인)
- "이 시점 이후 판정 로직을 바꾸지 않는다"는 문장

`python tools/freeze_holdout.py verify --folder <복제 폴더>`가 평가 직전에 **판정 코드·설정·파일 목록이 동결 이후 바뀌지 않았는지** 확인한다(바뀌었으면 종료 코드 1). 판정 코드는 `src/bcut/`의 `score/`, `detect/`, `imageio/`, `scan.py`, `config.py`다. **이 파일들은 수정하지 않는다.** 이미 동결 기록이 있으면 `freeze`는 다시 쓰지 않는다.

실제 기록: 홀드아웃 560장, 도구 0.1.0, 기본 설정(눈 감김 후보 0.134·확인 0.162 등), 테스트 383개 통과(1개 건너뜀), 판정 코드 해시 `46b22dd5d043…`.

## 2. 준비 (제가 하되, 시작 전에 승인을 받는다)

1. **복제 — 완료 (2026-10-20):** 560장을 복제했다(파일 수·크기 전부 일치, 무작위 12장 SHA-256 일치, 개발용 400장과 겹치지 않음). iCloud 원본을 직접 열지 않고, 홈 폴더로 복제한다 — `~/photo-select-data/events/260223_EVENT_A_holdout560/` (13.2GB, 같은 볼륨이라 APFS 복제로 빠르고 거의 공간을 안 쓴다, 여유 공간 127GB). iCloud 폴더 안에서 Capture One이 캐시를 쓰면 동기화가 꼬이기 때문이다. **원본 폴더에는 아무것도 쓰지 않는다.**
2. **새 카탈로그 — 완료 (2026-10-20):** 이름 `HOLDOUT560`, 위치 `~/photo-select-data/catalogs/`, 현재 위치에서 가져오기. 읽기 전용 검증: 560장, 파일 `PHA_7780`~`PHA_8739`(기대 번호와 일치), 전부 복제 폴더를 가리킴, 이름 목록 해시가 동결 기록과 같음, 태그·별점·키워드 0장. **다음: 1회차 라벨링(`PHA_7780`~`7982`, 203장).**

## 3. 라벨링 (사용자) — 기존 방식 그대로

색과 의미는 [labeling-guide.md](labeling-guide.md) 2장과 같다: **빨강** 눈 감김, **주황** 흔들림, **노랑** 초점 실패, **초록** 노출, **파랑** 표정 주의(눈을 가늘게 뜬 웃음 등, 결함 아님), **보라** 애매, 태그 없음 = 정상. 한 컷에 결함이 둘 이상이면 가장 분명한 하나만.

**3번에 나눠서 한다** (연사가 중간에 잘리지 않도록 촬영 순서대로 이어지는 구간):

| 회차 | 범위 | 장수 |
|---|---|---|
| 1 | `PHA_7780` ~ `PHA_7982` | 203 |
| 2 | `PHA_8383` ~ `PHA_8561` | 179 |
| 3 | `PHA_8562` ~ `PHA_8739` | 178 |

회차마다:
1. **1차 훑기:** 한 장씩 화면에 맞춰 보면서 눈에 띄는 결함과 의심 표정(파랑·보라)을 표시한다.
2. **2차 100% 확대 확인:** 태그가 없는 컷을 100%로 확대해 얼굴·주 피사체의 흔들림·초점을 본다 (이 단계를 건너뛰면 "정상" 속에 숨은 결함이 섞여 미탐이 과소평가된다).
3. **점검:** 보라(애매)가 그 회차의 20%를 넘으면 기준이 너무 엄격한 것이니 몇 장을 다시 보고 정한다.
4. 회차가 끝나면 **Capture One을 종료**해 저장을 확정한다 (사진은 읽기만 하고 카탈로그에만 태그가 저장된다).

**소요 시간:** 앞서 400장을 할 때의 약 1.4배(560÷400)로 보면 된다. 한 번에 몰아서 하지 않고 회차마다 쉬어도 된다(회차 사이에 도구 결과는 보지 않는다).
**기대 장수** (400장 구간 비율로 추정, 틀릴 수 있음): 눈 감김 B 약 65장, 표정 주의 약 90장, 실제 흔들림·초점·노출 결함은 거의 없을 가능성.

## 4. 라벨 내보내기 (제가 한다)

세 회차가 모두 끝나고 Capture One을 종료한 뒤:

```bash
python3 tools/export_labels.py "$HOME/photo-select-data/events/260223_EVENT_A_holdout560" \
    --catalog "$HOME/photo-select-data/catalogs/HOLDOUT560.cocatalog" --out eval/labels_raw_holdout.csv
python3 tools/build_labels.py eval/labels_raw_holdout.csv \
    --source "260223 EVENT_A SJ (holdout)" --out eval/labels_holdout.csv
```

점검: 560장이 모두 있는지, 파일 이름 목록 해시가 동결 기록과 같은지, 보라(애매)와 B·파랑 장수.

## 5. 평가 (제가 한다, 한 번만)

1. 동결한 설정 그대로 `bcut scan`을 560장에 돌린다.
2. 새 평가 스크립트(`eval/evaluate_holdout.py`, 라벨이 생긴 뒤 만든다)가 한 번에 표로 낸다:
   - 눈 감김 정탐률: **장 단위·묶음 단위**, 후보만 / 후보+확인, 95% 구간(Wilson, 묶음 단위는 묶음을 단위로)
   - **후보 오탐:** 정상(OK)·표정 주의(OK_EXPR)인데 후보(`candidate`)가 된 컷 수와 비율, **표정 주의에서 걸리는 수를 따로**
   - 확인 부담: 정상·표정 주의 중 `review`가 된 컷 수
   - 흔들림·초점·노출: 실제 결함이 있으면 정탐을, 없으면 **정상 컷에서 걸린 수(오탐)** 만 보고
   - 도구가 못 읽은 컷(`read_error`), 판정 불가
3. 같은 표를 **개발 데이터(E2)의 결과와 나란히** 놓아 어디서 달라지는지 본다.

**합격 기준 (결과를 보기 전에 정한다) [제안, 사용자 확정 필요]:**

| 지표 | 기준 |
|---|---|
| 눈 감김 정탐률 (장 단위, 후보+확인) | **50% 이상이면 의미 있음, 70% 이상이면 우수** (95% 구간 아래쪽도 함께 보고) |
| 후보 오탐 (정상·표정 주의 중 `candidate`) | **2장 이하** (정상·표정 주의 약 490장의 약 0.4%, A 엄격의 0.3% 수준) |
| 표정 주의에서 후보로 걸린 컷 | 따로 보고. 기준은 위 오탐에 포함 |
| 흔들림·초점·노출 | 정탐은 실제 결함 20장 이상일 때만 평가, 아니면 "미측정". **정상 컷에서 후보(`candidate`)로 걸리면 안 되고**(애초에 review 전용), review로 걸린 수는 부담으로 보고 |

**결과가 기준에 못 미치면:** 임계값을 H에 맞춰 바꾸지 않는다. 원인을 분석해 기록하고(어떤 유형이 놓쳤나/걸렸나), 고친다면 **새 행사**로 다시 평가한다. 그 사이 운영 등급은 지금처럼 눈 감김 `candidate`, 나머지 `review` 전용을 유지하고, 오탐이 기준을 넘으면 눈 감김도 `review` 전용으로 낮춘다(설정 `reason_tiers`).

## 6. 산출물

`eval/holdout-freeze.json`, `eval/labels_holdout.csv`, `eval/evaluate_holdout.py`, `docs/holdout-report.md`(결과표와 해석). 결과는 G3(출시 판단)의 정확도 근거로 쓴다.

## 7. 한계

- 같은 행사·같은 카메라 설정의 사진이라 **새 행사에서의 성능을 보장하지는 않는다.** 이 평가는 "임계값을 정한 사진에서만 잘 맞은 것이 아닌가"를 확인하는 것이다. 다른 촬영 조건은 처음 3개 행사의 기록(D11)으로 본다.
- 라벨은 한 사람이 붙인 것이다. 사람의 판단 오류와 도구의 오류가 구분되지 않는다.
- 이 행사에는 최종 선택(A컷) 표시가 없어 "최종 A컷이 후보로 걸리는지"는 여기서 보지 못한다(EVENT_B 16장으로만 확인).
