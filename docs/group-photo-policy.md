# 단체 사진 정책 (여러 명이 찍힌 컷)

> 결정일: 2026-10-19 · 구현: [src/bcut/score/eyes.py](../src/bcut/score/eyes.py) (`classify_eyes`, 테스트 12개 추가, 전체 70개 통과)
> 평가: [eval/check_eyes_defaults.py](../eval/check_eyes_defaults.py), [eval/evaluate_eyes.py](../eval/evaluate_eyes.py) (운영 코드를 그대로 사용)

## 1. 결정

**가장 큰 얼굴과 비슷한 크기의 얼굴을 모두 보고, 비슷한 크기의 얼굴이 둘 이상이면 후보로 확정하지 않고 항상 "사람이 확인"으로 보낸다.** (선택지 3번)

| 규칙 | 값 |
|---|---|
| "비슷한 크기" | 가장 큰 얼굴 면적의 **0.5배 이상** (제안값, `group_face_ratio`) |
| 사진의 등급 | 비슷한 크기의 얼굴들 중 **가장 높은 등급**(후보 > 확인 > 정상)을 얼굴이 하나인 것처럼 정한다. 같은 등급이면 더 감긴 얼굴 |
| 단체 사진에서 후보가 나오면 | `candidate`로 확정하지 않고 **`review`** 로 내리고 note에 `group`을 남긴다 (`group_downgrades_candidate = True`) |
| 작게 찍힌 뒷사람 | 비슷한 크기가 아니므로 **보지 않는다** |
| 눈이 좁은 얼굴(`small_eye`) 규칙 | 비슷한 크기의 얼굴마다 각각 적용한다 |

**한 명만 찍힌 사진은 달라지지 않는다.** 기존 테스트 58개가 그대로 통과했다.

## 2. 왜 이렇게 정했나

1. 단체 사진에서 누가 눈을 감았든 사진은 쓰기 어려운 경우가 많아서 **주인공만 보면 놓치는 것이 있다.**
2. 그런데 **도구는 누가 중요한 사람인지 모른다.** 그래서 후보로 확정하지 않고 사람이 판단하게 한다. 후보 앨범에 멀쩡한 컷이 섞이지 않게 하자는 Q7 "A 엄격" 결정과 같은 방향이다.
3. 뒷사람까지 모든 얼굴을 보면 흐릿한 작은 얼굴 때문에 확인할 컷이 늘어난다 (EVENT_A에서 확인 +6장). 그래서 비슷한 크기로 제한했다.

## 3. 데이터로 본 영향

사진 한 장에 얼굴이 몇 개인가:

| 행사 | 0명 | 1명 | 2명 | 3명 | 4명 이상 | 여러 명인 사진 |
|---|---|---|---|---|---|---|
| EVENT_A (개인 촬영) | 12 | 378 | 7 | 0 | 0 | **7장 (2%)** |
| EVENT_B (행사, 포토월) | 10 | 71 | 40 | 15 | 2 | **57장 (41%)** |

운영 코드로 평가한 결과 (기본 설정, 주 얼굴만 보던 옛 정책과 비교):

| 행사 | 항목 | 옛 정책 (주 얼굴만) | **새 정책 (확정)** |
|---|---|---|---|
| **EVENT_A** | 눈 감김 47장 → 후보 / 확인 / 놓침 | 31 / 14 / 2 | 31 / 14 / 2 (**변화 없음**) |
| | 정상+표정 주의 350장 → 후보 / 확인 | 1 / 11 | 1 / 11 (**변화 없음**) |
| **EVENT_B** | 눈 감김 1장 | 후보 | **확인** (단체 사진이라 후보가 확인으로) |
| | 정상 116장 → 후보 / 확인 | 0 / 2 | 0 / 7 (좁은 눈 5) |
| | 표정 주의 21장 → 후보 / 확인 | 0 / 0 | 0 / 1 |
| | 최종 선택(별점 5) 16장 → 후보 / 확인 | 0 / 0 | **0 / 2** |

- **EVENT_A는 숫자가 하나도 바뀌지 않았다.** 개인 촬영이 많은 행사에서는 이 정책이 사실상 영향이 없다.
- **EVENT_B에서는 사람이 확인할 컷이 137장 중 2장에서 8장으로 늘었다** (4%p). 후보 오탐은 늘지 않았다 (0장).
- **최종 선택 16장 중 2장이 "사람이 확인" 앨범에 올라온다.** 후보로는 올라오지 않는다. 좋은 컷을 사람이 한 번 더 훑게 되는 비용이다.
- 새로 확인에 올라온 컷 중 단체 사진의 **눈이 좁은 얼굴(고개가 돌아간 사람)** 때문인 것이 많다 (정상 116장 중 좁은 눈 5장).

## 4. 한계와 확인할 것

| # | 내용 | 대응 |
|---|---|---|
| 1 | **단체 사진 표본이 얇다.** 근거는 EVENT_B 57장(눈 감김은 1장)과 EVENT_A 7장뿐이다. 단체 사진에서 눈 감김을 실제로 얼마나 잘 잡는지는 **재현율을 측정하지 못했다** | 단체 사진이 많은 행사를 라벨링하면 확인한다 |
| 2 | **"비슷한 크기" 기준(0.5배)은 제안값**이다. 경계를 바꿔 본 적이 없다 | 처음 3개 행사를 쓴 뒤 Q7 재검토와 함께 본다 (설정 `group_face_ratio`) |
| 3 | **EVENT_B에서 새로 확인에 올라온 6장이 정말 눈이 감겼는지 확인하지 못했다.** 사진을 열어 본 것이 아니라 숫자만 본 것이다 | 사용자가 직접 확인: `PHB_7662`, `7663`, `7665`, `7684`, `7706`, `7726` (후보로 올라올 뻔한 것은 `7726`). 대부분 정말 감겼으면 정책이 맞고, 아니면 오판이니 `group_face_ratio`를 올려 본다 |
| 4 | **단체 사진에서는 후보가 없다.** 눈 감김이 확실해도 `review`다. 단체 사진이 많은 행사에서는 후보 앨범으로 한꺼번에 제외할 수 있는 컷이 줄어든다 | 후보로 확정하고 싶으면 `group_downgrades_candidate`를 끈다 (선택지 2번) |
| 5 | 눈이 좁은 얼굴 규칙이 단체 사진의 **다른 사람**에게도 적용되어 확인이 늘 수 있다 | 부담이 크면 `min_eye_width_frac`을 낮추거나 끈다 |

## 5. 설정 (코드의 기본값이며, 설정 파일 연결은 T1.8에서)

| 설정 | 기본값 | 바꾸면 |
|---|---|---|
| `group_face_ratio` | 0.5 | 올리면 더 비슷한 크기의 얼굴만 본다. **1.0이면 주 얼굴만 본다 (옛 정책)** |
| `group_downgrades_candidate` | True | False로 하면 단체 사진에서도 후보를 확정한다 (선택지 2번) |
