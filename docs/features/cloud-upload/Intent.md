# Intent

이 파일은 **작업마다 갱신한다.** 무엇을 왜 하는지(문제·기대 결과·영향 범위·제약·열린 질문)를 한 곳에 적고, 개발은 이 파일과 기획 문서(IA, UJ, PRD, ERD, GLOSSARY, ADR)를 **함께 읽고** 시작한다.

> 마지막 갱신: 2026-10-20 · 현재 작업: **로컬 기록 클라우드 올리기 (S5-B)** · 상태: **구현 완료(커밋 전)**, 실제 계정 로그인 시험은 사람 QA 대기. 브랜치 `feature/select-mode`에서 이어서 작업. 이전 작업(셀렉 훑기 모드 S5)의 Intent·spec·plan은 [docs/features/select-mode/](docs/features/select-mode/)에 보관

## 0. 이 파일 쓰는 법

### 작업을 시작할 때
0. 개발 직전에는 **`write-spec-plan` 스킬**(`.claude/skills/write-spec-plan/`)로 [spec.md](spec.md)(무엇을·왜)와 [plan.md](plan.md)(어떻게)를 만들거나 고친다.
1. 아래 "현재 작업" 5개 항목을 새 작업에 맞게 다시 쓴다. 이전 작업은 "작업 이력"으로 내린다.
2. **IA → UJ → PRD → ERD → GLOSSARY → ADR** 순서로 읽고, 작업과 관련된 ID(FR, US, 화면, CUJ 단계, 테이블)를 5개 항목에 **그대로 인용한다.**
3. 문서끼리 다르면 **더 나중에 사용자가 정한 것**이 이긴다. 우선순위는 ADR > 이 파일(현재 작업) > PRD > IA·UJ > ERD 순서이고, 어긋난 문서는 이 작업에서 같이 고친다.

### 개발할 때
- 구현 단위는 PRD의 FR 번호, 화면은 IA의 화면 ID, 사용자 흐름은 UJ의 CUJ 단계, 데이터는 ERD의 테이블로 부른다 (4장 추적표).
- 용어는 GLOSSARY와 IA 용어 규칙을 따른다. 화면 문구에 "삭제", "남기기", "B컷 후보"를 쓰지 않는다.
- 판정 코드(`src/bcut/score/`, `detect/`, `imageio/`, `scan.py`, `config.py`)와 홀드아웃 560장은 건드리지 않는다.

### 작업을 끝낼 때
- 이 파일의 "작업 이력"에 결과를 한두 줄로 남긴다 (한 일, 못 한 일, 확인하지 못한 것).
- PRD의 상태·FR, IA의 화면 ID, UJ의 단계, ERD의 "적용 상태"를 코드와 맞춘다.
- 새로 정한 용어는 GLOSSARY에, 되돌리기 어려운 결정은 `docs/adr/`에 쓴다.

## 1. 현재 작업: 로컬 기록 클라우드 올리기 (S5-B)

### 1-1. 문제 (Problem)

- 훑기 모드의 표시(셀렉·보류·버릴 컷)와 훑기 기록은 **이 컴퓨터의 파일**(`marks.jsonl`, `reviews.jsonl`)에만 있다.
  슈파베이스 DB(`photo_marks`, `review_sessions`)는 만들어졌지만 **앱이 아직 거기에 쓰지 않아** 비어 있다 (ADR-0001, 0008).
- 그래서 컴퓨터를 바꾸거나 파일이 사라지면 표시가 없어지고, 장당 훑는 시간 같은 지표(FR-26)를 DB에서 볼 수 없다.
- 로그인(ADR-0006)은 설계만 있고 앱 화면에는 없다.
- 근거 문서: PRD 2장, ADR-0001·0003·0005·0006·0008, erd.md

### 1-2. 기대 결과 (Proposed outcome)

- 앱에서 **이메일·비밀번호로 한 번 로그인**하면, 훑기를 마칠 때·앱을 켤 때·몇 분마다 **표시와 훑기 기록이 자동으로 DB에 올라간다** (FR-29, 30).
- 요약 화면에 상태 표시(올림 N장 / 대기 N장 / 로그인 필요 / 실패)와 **지금 올리기** 버튼이 있다 (FR-31).
- 처음 올리기 전에 **무엇이 올라가고 무엇은 안 올라가는지** 한 번 안내하고 동의를 받는다 (FR-32).
- 인터넷이 없거나 로그인이 안 되어도 **로컬 기능은 그대로 되고**, 올리기만 대기한다. 다시 연결되면 이어서 올라가고 **두 번 올라가지 않는다** (FR-33).
- 올라가는 것은 **셀렉·보류·버릴 컷을 단 사진의 이름·크기와 표시, 훑기 기록뿐**이다. 사진 파일·사진 미리보기·폴더 경로는 올라가지 않는다.

### 1-3. 영향 범위 (Affected users and systems)

| 영역 | 파일·대상 | 변경 |
|---|---|---|
| 새 서버 모듈 | `src/bcut/ui/cloud.py` (+ 분리 시 `cloud_store.py`) | 슈파베이스 통신은 **이 파일에서만**(ADR-0003), 허용 주소는 `https://<프로젝트>.supabase.co` 하나 |
| 로컬 서버 | `src/bcut/ui/server.py` | `/api/cloud/status·login·logout·sync` 4개 길 |

| 로컬 저장 | `<data-dir>/cloud.json`(동의·올린 줄 번호), macOS 키체인(로그인 토큰) | 비밀번호는 저장하지 않음 |
| 안전 시험 | `tests/test_safety_rules.py` | 네트워크 금지 목록에 **`ui/cloud.py` 한 파일만 예외**, 나머지는 그대로 |

### 1-4. 제약 (Constraints)

| 종류 | 내용 |
|---|---|
| **예산** | 슈파베이스 무료 플랜. 새 라이브러리 없음(파이썬 기본 `urllib`) |
| **지켜야 할 정책** | 사진은 밖으로 나가지 않는다(ADR-0001). 삭제 없이 쌓기만(ADR-0005): 올리기는 **추가 + 취소 표시 갱신**만 한다. DB 열쇠는 **공개용(publishable)만** 쓰고 서비스·비밀 열쇠는 쓰지 않는다. 비밀번호·토큰을 코드·문서·커밋·로그에 쓰지 않는다 |
| **로컬 우선** | 표시는 항상 로컬에 먼저 저장. 올리기 실패가 훑기를 막지 않는다 |
| **표시 규칙** | 사진 한 장에 활성 표시는 하나(DB도 부분 유일 인덱스로 보장). 올릴 때 시간 순서대로 넣고 취소를 반영한다 |
| **쓰지 말아야 할 것** | 화면 코드의 외부 주소·`innerHTML`·`eval`, 서버의 다른 파일에서의 네트워크 사용 |
| **환경** | 앱 창은 `127.0.0.1`만 허용(변경 없음). 인터넷은 로컬 서버 프로세스만 쓴다 |
