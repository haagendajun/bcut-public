## 1. 해결하려는 문제

> 이 기능이 없어서 지금 무엇이 막히나

지금 앱은 도구가 의심한 컷을 모아 보여 주는 데 맞춰져 있다. 그런데 실제 일은 **좋은 사진을 고르는 것**이다. 그래서 이런 일이 막힌다.

| 막히는 것 | 지금은 어떻게 하나 | 근거 |
|---|---|---|
| 고른 결과를 앱에 남길 수 없다 | 앱 밖(Capture One, Finder)에서 따로 고른다 | Intent 1-1, ADR-0007 |
| 도구가 놓친 나쁜 컷을 표시할 수 없다 | 눈으로 찾기만 하고 표시할 방법이 없다 | 인터뷰 Q2 |
| 사진이 작거나 잘려 보여 판단이 어렵다 | 카드 목록에서 확대해서 본다 | 인터뷰 Q4 |
| 한 장씩 넘기며 정하는 흐름이 없다 | 마우스로 카드를 하나씩 눌러 크게 본다 | 인터뷰 Q1 |
| 화면에 정보가 많아 정신없다 | 태그·문구·버튼 사이에서 사진을 찾는다 | 인터뷰 Q4 |

기준 시간(손으로 하던 시간)은 측정하지 않기로 했다. 그래서 "몇 % 빨라진다"는 말은 하지 않는다.

## 2. 주요 사용자

> 누가, 어떤 장면에서 쓰나

**사용자:** 포토팀 셀렉 담당자 1명. 본인 Mac(맥북) 하나에서만 쓴다. 배포하지 않는다. [확정]

| 장면 | 상황 |
|---|---|
| **A. 행사 직후 고르기** | 행사 사진 1500장 안팎이 폴더에 있다. 이 중 100~300장을 고른다. 공항패션은 30장 이내 |
| **B. 의심 컷 지나가기** | 눈 감김 같은 명백한 나쁜 컷은 빨리 지나치고 싶다. 하지만 도구가 틀렸을 수도 있어서 완전히 숨기는 건 싫다 |
| **C. 실수 되돌리기** | 키를 잘못 눌렀다. 바로 되돌리고 싶다. 좋은 컷을 실수로 버리는 게 가장 무섭다 |
| **D. 마무리** | 다 훑은 뒤 결과를 확인하고, 셀렉한 사진을 폴더로 담는다 |

사용 환경: 키보드를 쓴다. 한 번에 사진 한 장을 크게 본다.

## 3. 핵심 기능과 요구사항

> 만들어야 할 것 목록. 번호는 PRD와 같다. MUST는 없으면 끝난 게 아니고, SHOULD는 되도록 넣는다.

각 요구사항 아래 "확인"은 **눈으로 확인하는 방법**(Given 이런 상태에서 / When 이렇게 하면 / Then 이렇게 보인다)이다.

### FR-21. 훑기 모드 (MUST)
- 요약 화면에 **훑기 시작**이 있다. 이미 표시가 있으면 **이어서 훑기**로 바뀐다.
- 사진을 **촬영 순서대로** 한 장씩 크게 보여 준다. 사진이 잘리지 않는다. [촬영 순서는 파일 이름순으로 대신한다 — 가정]
- 화면 아래에 이웃 사진 목록(필름스트립)이 있고, 지금 사진이 표시된다.
- ←/→로 이전·다음 사진으로 간다. Z로 100% 확대, Esc로 마친다.
- 도구가 의심한 사진은 필름스트립에서 **흐리게** 보인다. **D**로 "의심 컷 건너뛰기"를 켜고 끌 수 있다. 의심 컷도 언제든 열어서 표시할 수 있다.
- 위쪽에 **"셀렉 N장 · 본 사진 M / 전체 T"**가 보인다. 목표 장수는 정하지 않는다.
- R로 **보류한 사진만** 모아 볼 수 있다 (SHOULD).

확인
- Given 검사가 끝난 400장 폴더, When 훑기 시작을 누르면, Then 첫 사진이 화면 대부분을 차지하고 잘리지 않으며 아래에 필름스트립이 보인다.
- Given 의심 컷이 있는 사진 사이, When →를 누르면, Then 의심 컷도 한 장씩 나온다. D를 켜면 의심 컷은 건너뛴다.
- Given 표시가 1개 이상 있는 행사, When 요약 화면으로 돌아오면, Then 버튼이 "이어서 훑기"로 바뀌어 있다.

### FR-22. 표시 (MUST)
- 키 **S 셀렉 / M 보류 / X 버릴 컷**으로 표시한다. 표시하면 **자동으로 다음 사진**으로 넘어간다.
- **같은 키를 다시 누르면 표시가 해제**된다.
- 사진 한 장에는 표시가 **동시에 하나**만 있다. 새 표시를 달면 앞의 표시는 자동으로 취소된다(삭제하지 않고 취소 이력으로 남는다).
- 도구가 뭐라고 판정했든 사용자의 표시가 우선이다.
- 표시는 **누를 때마다 바로 저장**된다. 앱을 닫았다 열어도 남아 있다.
- 표시는 색 + 아이콘 + 글자로 보인다. 색만으로 구분하지 않는다.

확인
- Given 아무 표시 없는 사진, When S를 누르면, Then 셀렉 표시(색·아이콘·글자)가 뜨고 다음 사진이 열린다.
- Given 셀렉한 사진, When 그 사진에서 S를 다시 누르면, Then 표시가 사라진다.
- Given 셀렉한 사진, When X를 누르면, Then 버릴 컷으로 바뀌고 셀렉 표시는 없다.
- Given 표시를 몇 개 한 뒤, When 앱을 닫고 다시 열어 "이어서 훑기"를 누르면, Then 표시가 그대로 남아 있다.

### FR-23. 안전장치 (MUST)
- **⌘Z**로 직전 표시를 되돌린다. 표시와 보던 위치가 함께 돌아온다.
- 훑기를 마치면 **최종 확인** 화면이 뜬다: 셀렉 N장 / 보류 M장 / 버릴 컷 K장 / 표시 안 한 U장. 표시 안 한 사진이 많아도 막지 않고 숫자만 알려 준다.
- 최종 확인에서 **계속 훑기** 또는 **나누어 담기**를 고른다.
- 취소된 표시도 기록에는 남는다(삭제하지 않는다).

확인
- Given X를 방금 누른 상태, When ⌘Z를 누르면, Then 그 사진의 표시가 사라지고 그 사진이 다시 보인다.
- Given 셀렉 12장·보류 3장·버릴 컷 5장을 표시한 상태, When Esc로 마치면, Then 최종 확인에 12 / 3 / 5와 나머지 장수가 정확히 나온다.

### FR-24. 판단 돕는 정보 (SHOULD)
- 도구가 얼굴을 찾은 사진에는 **얼굴 박스**가 보이고(F로 켜고 끔), **눈 부분 확대**가 보인다.
- 도구가 의심한 사진에는 **이유 한 줄**과 의심 정도가 보인다 (예: "눈이 거의 감긴 것 같아요").
- 얼굴이 없는 사진은 해당 칸을 비워 둔다. 정보를 못 불러와도 훑기는 계속된다.

확인
- Given 얼굴이 있고 도구가 의심한 사진, When 크게 보면, Then 이유 한 줄과 눈 확대가 보이고 F로 얼굴 박스를 켜고 끌 수 있다.
- Given 얼굴이 없는 사진, When 크게 보면, Then 눈 확대 칸이 비어 있고 다른 조작은 정상이다.

### FR-25. 셀렉 폴더로 담기 (MUST)
- 나누어 담기에 **셀렉**(맨 앞)과 **보류** 폴더가 생긴다.
- 셀렉한 사진은 **셀렉 폴더에만** 담긴다. 보류는 보류 폴더에만 담긴다.
- 사용자가 정한 **버릴 컷**은 도구가 찾은 "버릴 것 같은 컷" 폴더에 합친다(기록에서는 구분된다).
- 표시 안 한 사진은 지금처럼 판정별 폴더(직접 확인, 이상 없음, 판단 못 함, 문제 종류별)로 간다.
- 미리보기가 기본이고, 원본은 읽기만 하며, 사본을 만들고, 파일을 삭제하지 않으며, 실행마다 새 폴더를 만든다.

확인
- Given 셀렉 12장·보류 3장이 있는 상태, When 나누어 담기 미리보기를 보면, Then 셀렉 12 / 보류 3 폴더가 맨 앞에 나오고 합계가 전체 장수와 맞는다.
- Given 담기를 실행한 뒤, When 원본 폴더를 보면, Then 아무것도 바뀌지 않았고 셀렉 폴더에는 셀렉한 사진만 있다.

### FR-26. 훑기 기록 (SHOULD)
- 훑기 한 번의 **시작·끝 시각, 본 사진 수, 셀렉·보류·버릴 컷 수**를 자동으로 기록한다.
- 이 기록으로 **장당 훑는 시간**을 계산할 수 있다.

확인: Given 훑기를 한 번 마친 상태, When 기록을 보면, Then 시작·끝 시각과 본 사진 수, 표시 수가 있고 (끝 − 시작) ÷ 본 사진 수가 계산된다.

### FR-27. 기존 "남기기" 정리 (MUST)
- 화면의 "남기기" 문구와 버튼을 없앤다. 기존에 "남기기"로 표시해 둔 사진은 **셀렉**으로 옮긴다.

확인: Given 예전에 남기기를 한 행사, When 새 화면을 열면, Then 그 사진들이 셀렉으로 보이고 화면 어디에도 "남기기"가 없다.

### 3-2. 예외 상황 (이럴 때도 동작해야 한다)

| 상황 | 기대 동작 |
|---|---|
| 키가 먹지 않는다 (창에 입력이 없음) | 화면을 한 번 클릭하면 다시 먹는다. 안내 문구가 있다 |
| 얼굴 정보 계산이 느리거나 실패 | 해당 칸만 비고 훑기는 계속된다 |
| 앱이 도중에 닫힘 | 다시 열면 표시가 남아 있다 |
| 잘못 표시한 채 담음 | 원본은 그대로다. 표시를 고치고 새 폴더로 다시 담는다 |
| 사진이 한 장뿐이거나 전부 의심 컷 | 훑기는 정상이다. D를 켜도 모두 건너뛰지 않고 안내한다 |
| 사진을 읽지 못한 컷(판단 못 함) | 훑기에서도 나오고 표시할 수 있다 |
| 같은 이름의 다른 사진 (크기가 다름) | 파일 이름 + 크기로 구분한다 |
| 세로 사진 | 똑바로 보인다 (이미 해결된 동작을 유지) |
| 1500장 | 넘기기와 필름스트립이 느려지지 않는다 |

### 3-3. 다루는 데이터

| 데이터 | 설명 | ERD |
|---|---|---|
| **표시** | 사진 한 장의 셀렉·보류·버릴 컷. 활성 표시는 하나, 바뀌면 앞의 것은 취소 | `photo_marks` |
| **훑기 기록** | 훑기 한 번의 시간·장수 | `review_sessions` |
| **담기 항목의 표시** | 담을 때 적용된 표시(없으면 비어 있음) | `sort_items.mark_kind` |
| **사진 구분** | 행사 이름 + 파일 이름 + 크기 (ADR-0004) | `photos` |

DB 쪽 변경은 4단계에서 적용한다. 그 전에는 이 컴퓨터 안에만 저장한다.

### 3-4. 행동 규칙 (항상 / 먼저 물어보기 / 절대 안 함)

| 구분 | 내용 |
|---|---|
| **항상** | 원본은 읽기만 한다. 표시는 누를 때마다 바로 저장한다. 화면 문구는 GLOSSARY의 용어를 쓴다. 코드를 바꾸면 기존 테스트를 모두 돌린다 |
| **먼저 물어보기** | DB 변경을 실제 DB에 적용할 때. 새 라이브러리를 넣을 때. 판정 코드 쪽을 읽거나 호출하는 방식을 바꿀 때 |
| **절대 안 함** | 파일 삭제. 판정 코드 수정. 홀드아웃 560장 검사. 사진 외부 전송. 의심 컷을 숨기기(흐리게만 한다). 표시를 색만으로 구분하기 |

## 4. 성공 기준

> 무엇이 되면 "끝"인가. 눈으로 확인할 수 있게. 기술 이름은 쓰지 않는다.

**"끝" = SC-01~09, SC-11이 모두 되는 것.** SC-10은 4단계(DB 적용)까지 끝나야 한다.

| # | 눈으로 확인하는 방법 | 관련 FR |
|---|---|---|
| SC-01 | 400장·1500장 폴더에서 훑기 시작 후 **첫 사진이 2초 안에** 크게 보이고, →를 누르면 **0.3초 안에** 다음 사진이 보인다 **[제안, 수치는 측정 후 확정]** | FR-21 |
| SC-02 | S / M / X를 누르면 표시(색·아이콘·글자)가 뜨고 자동으로 다음 사진이 열린다 | FR-22 |
| SC-03 | 같은 키로 해제되고, ⌘Z로 직전 표시와 위치가 돌아온다 | FR-22, 23 |
| SC-04 | 앱을 닫았다 열어 "이어서 훑기"를 누르면 표시가 그대로다 | FR-22 |
| SC-05 | 의심 컷이 흐리게 보이고 D로 건너뛰기를 켜고 끌 수 있다. 의심 컷도 셀렉할 수 있다 | FR-21, 22 |
| SC-06 | 최종 확인의 숫자가 실제 표시 수와 같다 | FR-23 |
| SC-07 | 담기 미리보기·결과에서 셀렉 폴더에 셀렉만, 보류 폴더에 보류만 있고, 원본 폴더는 **변화 0**, 삭제된 파일 **0** | FR-25 |
| SC-08 | 화면 어디에도 "남기기", "삭제", "B컷 후보" 문구가 없다 | FR-27 |
| SC-09 | 기존 테스트 453개가 모두 통과하고 새 기능 시험이 추가되어 통과한다. 검사 규칙(판정 코드)은 바뀌지 않았다 | 전체 |
| SC-10 | 훑기 기록에서 장당 훑는 시간을 계산할 수 있다 (4단계 후) | FR-26 |
| SC-11 | 사용자가 직접 하는 QA 시트의 항목이 모두 Pass다 (앱 창에서 키 입력·끌어놓기 포함) | 전체 |

## 5. 제외 범위

> 이번에 일부러 안 만드는 것

| 제외 | 이유 / 어디서 다루나 |
|---|---|
| **Capture One에 표시하기** (키워드 부여) | S6 별도 단계 (PRD FR-28, 사용자 결정 2026-10-20) |
| 별점·컬러 태그를 직접 주는 것 | 기존 작업을 덮어쓸 수 있어 하지 않기로 함 |
| 연사·비슷한 사진 묶기 | 사용자가 범위 밖으로 정함 |
| 나누어 담은 뒤 되돌리기 전용 화면 | 범위 밖 |
| 지난 검사 이력 목록 | 범위 밖 |
| 판정 규칙 변경, 새 판정 추가 | 판정 코드는 수정하지 않는다 (동결) |
