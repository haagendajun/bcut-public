### 2-2. 표시를 어디에 저장하나 **[제안, spec 확인 필요 ★1]**

- 표시는 **행사 단위**로 저장한다. 검사(작업 번호)는 다시 하면 바뀌지만 표시는 유지되어야 한다 (ADR-0004).
- 행사 구분 키: 폴더 이름(기본 행사 이름) **[제안]**. 사진 구분: **파일 이름 + 파일 크기** (ADR-0004). 파일 크기는 서버가 `os.stat`으로 읽어 결과 행에 `size`로 붙인다(검사 코드 변경 없음).
- 저장 위치: `<data-dir>/events/<행사 키>/marks.jsonl` (앱에서는 `~/Library/Application Support/bcut/data/`). 한 줄에 사건 하나를 **덧붙이기만** 한다(수정·삭제 없음, ADR-0005와 같은 정신).

```
{"id":"<uuid>","file":"PHA_7780.CR3","size":24633012,"kind":"pick","at":"2026-10-20T11:00:00+09:00"}
{"id":"<uuid>","cancel":"<위 id>","at":"2026-10-20T11:00:05+09:00"}
```

- 현재 상태는 파일을 위에서부터 읽어 "취소되지 않은 마지막 표시"로 계산한다. 새 표시는 (앞 표시 취소 줄 + 새 줄)을 **한 번에 쓴다**.
- 훑기 기록은 같은 폴더의 `reviews.jsonl`에 훑기가 끝날 때 한 줄을 덧붙인다.
- 4단계에서 같은 줄들이 DB의 `photo_marks`, `review_sessions`로 올라가도록 필드 이름을 ERD와 맞춰 두었다(`kind`: pick/maybe/discard).

### 2-3. API 설계 **[제안]**

모두 기존 규칙을 따른다: `127.0.0.1`만, 토큰 필수, 파일 이름은 이 작업의 결과에 있는 것만 허용(경로 조작은 404), 요청 본문 크기 제한.

| 요청 | 하는 일 |
|---|---|
| `GET /api/jobs/<job>/marks` | 이 행사의 현재 표시 목록 `{marks:[{file,size,kind}]}` |
| `POST /api/jobs/<job>/marks` `{file, kind \| null}` | 표시 달기/해제. 앞 표시는 자동 취소. 취소된 이력은 파일에 남음 (서버가 PUT을 허용하지 않아 POST로 함) |
| `GET /api/jobs/<job>/faces/<파일>` | 얼굴 박스·눈 위치 `{w,h,faces:[{box,area,eyes}]}` (사진 크기에 대한 비율, 원점 왼쪽 위). 기존 얼굴 인식을 불러서 계산하고 한 번만 계산해 기억 (FR-24, **3단계 구현 완료**) |
| `POST /api/jobs/<job>/review` `{id, started_at, ended_at, seen, pick, maybe, discard}` | 훑기 기록 저장 (FR-26, **4단계 로컬 부분 구현 완료**). 같은 id는 한 줄만 남음, 잘못된 값은 400. 행사 폴더의 `reviews.jsonl`에 덧붙임 |
| `POST /api/jobs/<job>/sort` (기존) | 담기에 현재 표시를 반영. 기존 `rescue` 입력은 제거하고 표시로 대체 |

실행 취소(⌘Z)는 서버 API 없이 화면이 **이전 표시를 다시 보내는** 방식으로 한다(해제 또는 이전 표시 복원). 그래서 서버 규칙(한 장에 하나, 이력 보존)이 그대로 지켜진다. **(2단계 구현 완료)** 셀렉·보류·버릴 컷은 화면이 보낸 값이 아니라 서버에 저장된 표시를 서버가 읽어 담기에 쓴다.

### 2-4. 앱(Electron) 주의: ⌘Z **[확인함]**

`electron/main.js`의 "편집" 메뉴에 `{ role: 'undo' }`가 있다. macOS는 이 메뉴의 기본 단축키(⌘Z)를 먼저 처리하기 때문에, 화면의 `keydown` 처리기로 ⌘Z가 **전달되지 않을 가능성**이 크다. 해결 후보(구현 1~2단계에서 정한다):

1. 메뉴 항목을 "실행 취소"(⌘Z, 화면에 신호만 보냄)로 바꾸고 `preload.js`에 신호 수신 기능을 추가한다. 시험(`test_electron_shell.py`의 열어 준 기능 목록)을 같이 고친다.
2. 훑기 화면에서만 메뉴의 undo를 막는다.

둘 다 앱 창에서 **사람이 직접 눌러 확인**해야 한다(제가 앱 창을 눈으로 확인하지 못한다).

**2단계에서 고른 방법:** 두 후보 중 1번의 변형이다. 메뉴 항목을 "실행 취소(⌘Z)"로 직접 만들고, 클릭하면 화면에 `bcut-undo` 신호(고정 문장 하나)를 보내 훑는 중이면 화면이 되돌리고, 아니면 기본 동작(글자 되돌리기)을 한다. 이렇게 해서 `preload.js`는 바꾸지 않았다(화면에 열어 준 기능 3개 그대로).

## 5. 제약과 주의점

> 지켜야 할 것

| 구분 | 내용 |
|---|---|
| **비밀 키 노출 금지** | 슈파베이스의 secret/service role 키, 비밀번호, 토큰을 코드·문서·화면·커밋에 쓰지 않는다. 화면(브라우저 쪽)에는 공개용 키만 허용된다. 4단계의 DB 통신은 서버 쪽 파일 하나에서만 하고 키는 이 컴퓨터의 키체인에 둔다(ADR-0003, 0006). 이번 1~3단계는 슈파베이스와 통신하지 않는다 |
| **속도** | 1500장에서 필름스트립은 보이는 부분만 그리고 썸네일을 캐시한다. 얼굴 정보는 크게 볼 때만 계산하고, 느리면 다음 사진을 미리 불러온다. 목표는 spec SC-01 |
| **지금 돌아가는 기능을 깨지 않기** | 검사, 우선순위 요약, 사진 보기, 나누어 담기, 폴더 선택이 그대로 동작해야 한다. 단계마다 전체 시험을 돌린다. 기존 "정리" 결과 폴더 형식과 `정리 기록.json`은 필드를 **추가만** 한다 |
| **판정 코드·홀드아웃** | `score/`, `detect/`, `imageio/`, `scan.py`, `config.py`는 수정하지 않는다. 홀드아웃 560장은 검사하지 않는다 |
| **삭제 금지** | 파일 삭제 호출을 만들지 않는다 (안전 시험이 검사). 표시 저장도 덧붙이기만 한다 |
| **네트워크 규칙** | 화면에서 외부 주소를 부르지 않는다. 서버의 `http` 사용은 기존 파일 한 곳으로 제한(ADR-0003) |
| **표시 소실 방지** | 표시는 누를 때마다 바로 저장한다. 저장에 실패하면 화면에 알린다(조용히 넘어가지 않는다) |
| **접근성** | 표시는 색 + 아이콘 + 글자. 어두운 화면에서도 글자 대비를 확인한다 |
| **용어** | GLOSSARY와 IA 13-6을 따른다. "남기기", "삭제", "B컷 후보" 문구를 화면에 쓰지 않는다 |
| **환경 주의** | 코드를 고치면 `bash electron/build.sh`로 앱을 다시 만들어야 반영된다(앱은 복사본으로 동작). 앱이 켜져 있으면 닫고 빌드한다. 이 프로젝트가 있는 Desktop은 iCloud와 동기화되므로 가상환경을 프로젝트 안에 두지 않는다 |
| **QA 화면(Vercel)** | `supabase/qa`는 이번 작업에서 바꾸지 않는다. push하면 자동 배포되지만 내용이 같아 영향 없다 |

### 위험과 대응

| # | 위험 | 가능성 | 영향 | 대응 |
|---|---|---|---|---|
| R1 | 편집 메뉴의 기본 "실행 취소"가 ⌘Z를 가로챔 (2-4) | 높음 | 안전장치 핵심이 안 먹음 | 2단계에서 메뉴 처리 방식 결정, 사람이 앱에서 확인 |
| R2 | 얼굴 정보 계산이 느림 (사진 1장당) | 중간 | 크게 볼 때 지연 | 3단계에서 실측, 미리 불러오기, 실패 시 칸만 비움 |
| R3 | 표시 파일이 깨지거나 사라짐 | 낮음 | 셀렉한 결과 손실 | 덧붙이기만 하는 형식, 읽을 때 깨진 줄은 건너뛰고 알림 |

| R5 | 1500장 필름스트립이 무거움 | 중간 | 넘기기 지연 | 보이는 부분만 그리기, 합성 1500행으로 측정 |
| R6 | 표시 키가 앱 창에서 먹지 않음 (포커스) | 중간 | 훑기 불가 | 클릭 시 포커스 복구, QA 시트에서 확인 |

★1 표시 저장 방식(2-2의 제안을 사용자가 확인), ★2 예전 "남기기" 이전 범위, ★3 파일 이름순 = 촬영순 여부, 4 얼굴 정보 계산 시간, 5 앱 창 키 입력(⌘Z 포함), 6 보류 재확인 방식, 7 SC-01 시간 목표, 8 DB 적용 시점.
