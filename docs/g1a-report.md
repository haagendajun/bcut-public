# G1a 체크포인트 보고: 눈 감김만으로 합격 기준을 충족하는가

> 평가일: 2026-10-19 · 코드: [eval/evaluate_eyes.py](../eval/evaluate_eyes.py), [eval/time_pipeline.py](../eval/time_pipeline.py), [src/bcut/evaluation.py](../src/bcut/evaluation.py) (단위 테스트 12개, 전체 58개 통과)
> 데이터: **E2** = EVENT_A 구간 397장 (눈 감김 B 47장·연사 묶음 25개, 표정 주의 63, 정상 287), **E1** = EVENT_B 138장 (B 1, 표정 주의 21, 정상 116, 최종 선택 16). 애매 제외.
> 합격 기준은 devplan G1의 **제안값**이다. 오탐 허용 범위 Q7은 2026-10-19에 **A 엄격으로 확정**됐다 (처음 3개 행사를 쓴 뒤 재검토).

## 1. 결론

**G1a는 조건부 통과다.** 눈 감김은 제안한 합격 기준을 모두 충족했다. 다만 표본이 한 행사의 25개 연사 묶음이라, **최종 확인은 홀드아웃(Phase 4)에서 한다.**

| 합격 기준 (제안값) | 결과 | 판정 |
|---|---|---|
| 눈 감김 장 단위 재현율(후보+확인) 50% 이상 의미, 70% 이상 우수 | **94%** (44/47), 95% 구간 83~100% | **우수** |
| 눈 감김 장 단위 재현율(후보만) | **64%** (30/47), 95% 구간 49~89% | 의미 있음 |
| 눈 감김 묶음 단위 재현율 | **100%** (25/25) | **우수** |
| 최종 선택 컷이 후보로 걸린 수 (한두 장 이내) | E1 최종 선택 16장 중 **0장** | 충족 |
| 후보 오탐 (0에 가깝게) | E2 **1/350** (0.29%), E1 0/137 | 충족 |
| 읽기 + 판정 속도 | 1장 67 ms, 1500장 병렬 약 22초 | 허용 시간(Q4) 미정, 부담 없는 수준 |
| 네트워크 미사용·삭제 호출 금지 | 코드 검사 테스트 통과 | 충족 (`scan` 단위 읽기 전용 테스트는 T1.10 이후) |

## 2. 평가 방법

- **E2는 시간순 4블록 교차 검증**이다. 임계값(candidate, review)은 학습 블록에서만 정하고, 학습에 쓰지 않은 블록에서만 평가한다. 눈 감김 묶음이 블록 경계에서 잘리지 않게 경계를 조정했다 (경계 7983~8081 / 8082~8183 / 8184~8283 / 8284~8382).
- **E1은 새 행사 점검**이다. E2 전체로 정한 임계값을 그대로 적용한다 (B가 1장뿐이라 재현율은 보지 않는다).
- **신뢰구간은 연사 묶음을 단위로 다시 뽑아(부트스트랩)** 구한다. 같은 묶음의 컷은 거의 같아서 장 단위로 뽑으면 구간이 실제보다 좁게 나온다.
- 후보 오탐 같은 드문 비율은 윌슨 구간으로 구했다.

블록을 바꿔도 candidate 경계는 0.134~0.137로 거의 같고, review 경계는 0.152~0.165 사이다.

### 3-2. E2 합산 (학습에 쓰지 않은 블록에서만)

| 지표 | 값 | 95% 구간 |
|---|---|---|
| 눈 감김 장 단위 재현율 (후보+확인) | **44 / 47 (94%)** | 83% ~ 100% |
| 눈 감김 장 단위 재현율 (후보만) | 30 / 47 (64%) | 49% ~ 89% |
| 눈 감김 묶음 단위 재현율 | 25 / 25 (100%) | 100% ~ 100% (묶음 수가 25라 신뢰구간이 의미가 약함) |
| 놓친 눈 감김 | 3장 | |
| 후보 오탐 (정상 + 표정 주의 350장) | 1 / 350 (**0.29%**) | 0.05% ~ 1.60% |
| 　└ 표정 주의 63장 중 후보 | 1장 (1.6%) | 0.3% ~ 8.5% |
| 확인 부담 (사람이 직접 봐야 하는 음성 컷) | 11 / 350 (3.1%) | |
| 　└ 이 중 눈이 좁은 얼굴 규칙으로 올라온 컷 | 8장 | |
| 얼굴이 없어 판정하지 않은 음성 | 12장 | |

눈 감김 47장 중 7장은 **눈이 좁은 얼굴 규칙**(T1.5)으로 `review`에 올라왔다. 이 규칙의 경계는 E2를 보고 사후에 정한 값이라 교차 검증 밖에서 정해진 것이다. 위 94%에는 이 7장이 포함되어 있다.

### 3-3. review 경계 민감도

"학습 B의 몇 %를 review에 넣을지"에 따른 교차 검증 결과.

| 학습 B 포함 | review 경계 (E2 전체 학습) | 눈 감김 후보+확인 | 놓침 | 후보 오탐 | 확인 부담 | E1 확인(음성) |
|---|---|---|---|---|---|---|
| 80% | 0.135 | 38/47 (81%) | 9 | 1/350 | 8/350 (2.3%) | 6/137 |
| 90% | 0.146 | 42/47 (89%) | 5 | 1/350 | 11/350 (3.1%) | 6/137 |
| **95% (채택)** | **0.162** | **44/47 (94%)** | **3** | 1/350 | **11/350 (3.1%)** | 8/137 |
| 100% | 0.168 | 46/47 (98%) | 1 | 1/350 | 13/350 (3.7%) | 8/137 |

**95%로 잡으면 90%일 때와 확인 부담이 같으면서 눈 감김을 2장 더 올린다.** 100%는 1장 더 올리지만 확인 부담이 늘고, 표본이 작아 극단값에 끌릴 수 있어 95%를 기본값으로 정했다. 후보 오탐은 어느 경우에도 1/350으로 같다.

### 3-4. E1 새 행사 점검 (E2 전체로 정한 임계값 그대로: candidate 0.134, review 0.162)

| 항목 | 결과 |
|---|---|
| 최종 선택(별점 5) 16장 | 후보 **0장**, 확인 **2장** (단체 사진 정책으로 비슷한 크기의 다른 얼굴이 걸린 컷) |
| 음성 137장 | 후보 오탐 **0장**, 확인 8장 (눈이 좁은 얼굴 5장 포함), 얼굴 없음 10장 |
| 표정 주의 21장 | 후보 0장, 확인 1장 |
| 눈 감김 1장 | 확인 1장 (단체 사진이라 후보가 확인으로 내려감. 표본이 1장뿐이라 재현율은 의미 없음) |

**좋은 컷이 후보에 섞이는 일이 새 행사에서는 일어나지 않았다.** 최종 선택 16장 중 후보에 오른 것은 0장이다. 다만 2장은 단체 사진 정책 때문에 "사람이 확인" 앨범에 올라온다 ([group-photo-policy.md](group-photo-policy.md)). 이 표는 단체 사진 정책을 적용한 최종 결과이며, 단체 사진 정책을 적용하기 전에는 확인 컷이 더 적었다 (음성 확인 2장).

### 3-5. 속도 (읽기 + 얼굴 검출 + 판정, EVENT_A 400장)

| 방식 | 400장 | 1장당 | 1500장 추정 |
|---|---|---|---|
| 단일 처리 | 26.8초 | 67 ms (중앙값 63, 최대 386) | 약 1.7분 |
| 병렬 6개 | 5.8초 | 15 ms (4.6배) | **약 22초** |

주의: 병렬 측정은 같은 파일을 한 번 읽은 뒤라 디스크 캐시 이점이 조금 있을 수 있다. 눈 감김 판정만의 시간이며, 흔들림·초점·노출 판정이 추가되면 늘어난다.

## 4. 앞서 보고한 수치와 달라진 부분 (정정)

| | 이전 보고 (T1.5) | G1a 교차 검증 |
|---|---|---|
| E2 눈 감김 중 후보 또는 확인 | 47 / 47 (100%) | **44 / 47 (94%)** |
| 후보 오탐 | 1 / 350 | 1 / 350 (같음) |
| 확인 부담 | 16 / 350 (4.6%) | 11 / 350 (3.1%) |
| review 경계 | 0.187 | **0.162** |

- **이전의 100%는 경계를 같은 데이터(E2 전체)로 정해서 낙관적이었다.** 학습에 쓰지 않은 블록에서 평가한 94%가 정직한 값이다.
- 이전 review 경계 0.187은 **눈이 좁은 얼굴의 높은 점수(0.195~0.264)까지 포함해서** 정한 값이라 필요 이상으로 넓었다. 눈이 좁은 컷은 별도 규칙이 처리하므로 경계를 정할 때 빼니 0.162로 내려갔고, 확인 부담이 4.6%에서 3.1%로 줄었다.
- 기본값(`src/bcut/score/eyes.py`)을 **review 0.187 → 0.162**로 바꿨다. 관련 테스트를 고쳤다.

## 6. 다음 단계에 주는 영향

- **Phase 2(S3 `apply`/`rollback`)를 병행 시작할 수 있다.** 눈 감김 판정이 합격했고, 파일 계약의 사유 값(`eyes_closed` 등)은 이미 고정되어 있다 (devplan 1-F). 단, `scan`과 CSV(T1.9)가 만들어져야 `apply`가 읽을 입력이 생긴다.
- **T1.18(HTML 리포트)을 눈 감김 결과로 먼저 만들면** 이 평가 숫자를 사진으로 눈으로 확인할 수 있다 (1B+ 단계).
- **Q7은 A 엄격으로 확정**됐다 (처음 3개 행사 후 재검토). **단체 사진 정책도 확정**됐다 (비슷한 크기 얼굴을 모두 보되 후보는 확인으로).
