# CUJ-01: 행사 후 1차 컷 (명백한 B컷 걷어내기)

> 작성일: 2026-10-19 · 상태: 초안 (S1 검증 전)

## 개요

| 항목 | 값 |
|---|---|
| **유형** | OEC-Based (성공 기준 "② 단계 50% 단축") + High-Traffic (매 행사마다 수행) |
| **우선순위** | Critical |
| **사용자** | 포토팀 셀렉 담당자 (Capture One, iMac 사용) |
| **빈도** | 행사마다 (사진 300~1500장) |
| **성공 지표** | ② 1차 컷 장당 소요 시간 50% 이상 단축, 오탐 거의 0 |
| **관련 OEC** | 셀렉 시간 단축 + 품질 현재 수준 유지 |

## 사용자 목표 (JTBD)

> "나는 행사 사진 300~1500장을 받은 상황에서, 눈 감김·흔들림·초점 실패 같은 명백한 B컷을 한 장씩 눈으로 걷어내는 시간을 줄여서, 좋은 컷을 고르는 일에 집중하고 싶다. 단, 좋은 컷이 묻히면 안 된다."

## 사전 조건

- 사용자 상태: 행사 촬영 완료, 사진이 폴더에 있다
- 환경: iMac, Capture One 16.8.6 이상 (현재 16.7.1이라 업데이트 필요), **네트워크로 사진을 보내지 않는다**
- 데이터 상태: 인물·음식·현장 컷이 한 폴더에 섞여 있다. 원본은 읽기만 한다.
- 도구 상태 (S2 기준): 임계값 보정이 끝나 있다 (F5, `PR-02-CLI`)

### 단계별 성공 기준과 잠재 불편

**Step 2: 후보 분석**
- 성공 기준: [ ] 1500장도 사용자가 기다릴 만한 시간 안에 끝난다 (허용 시간은 미정, 열린 질문) [ ] 네트워크 없이 동작한다 [ ] 끝나면 요약이 바로 보인다
- 잠재 불편: 대용량 RAW 처리가 길다 → 내장 JPEG 프리뷰 사용 검토 (미검증) / 진행 상황이 안 보인다 → 진행률 표시

**Step 4: 반영**
- 성공 기준: [ ] 기존 별점·컬러 태그가 바뀌지 않는다 [ ] 전용 키워드(`bcut-*`)만 붙는다 [ ] 반영 직전 백업이 저장된다
- 잠재 불편: 수천 장 일괄 적용이 느릴 수 있다 (미검증) → 장수별 소요 시간 기록

**Step 5: 후보 확인 ★**
- 성공 기준: [ ] 사유가 컷마다 보인다 [ ] 최종 A컷으로 뽑힐 컷이 후보에 걸린 경우가 거의 없다 [ ] 후보 앨범을 훑는 시간이 기존 전수 비교보다 확연히 짧다
- 잠재 불편: 연사 중 의도적 표정(눈을 가늘게 뜬 웃음)이 눈 감김으로 걸린다 → 확신도 낮게 분류해 "사람이 확인"으로 보낸다

## 에러 시나리오

### E1: 분석이 일부 사진에서 실패한다
- **트리거**: 손상된 파일, 지원하지 않는 형식
- **사용자가 보는 것**: 요약에 "처리 못 한 사진 K장"과 파일명 목록
- **복구 경로**: 해당 컷은 자동으로 "사람이 확인" 앨범으로 보낸다. 분석 전체가 중단되지 않는다.
- **검증 방법**: 일부러 손상된 파일을 섞어 실행

### E2: 후보 비율이 이상하게 높다 (예: 절반 이상)
- **트리거**: 임계값이 맞지 않거나 어두운 현장 행사
- **사용자가 보는 것**: 요약에서 후보 비율이 크게 표시됨
- **복구 경로**: 반영 전에 요약을 먼저 보여주므로 `apply`를 하지 않고 `calibrate`로 돌아간다 (IA F5)
- **검증 방법**: 어두운 행사로 비율 확인

### E3: 반영 후 결과가 이상하다
- **복구 경로**: `rollback`으로 원래 별점·태그를 복구한다 → [CUJ-03](CUJ-03-오탐복구.md)
